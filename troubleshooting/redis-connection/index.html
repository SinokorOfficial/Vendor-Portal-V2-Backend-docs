    Redis 연결 끊김 진단¶

    RedisCommandTimeoutException / QueryTimeoutException: Redis command timed out 이 보이고, 로그인·세션 확인·조회 등 엔드포인트를 가리지 않고 일부 요청이 500 이 날 때 보는 문서. 2026-09-29 운영 5xx 알림 조사에서 확립했다.

    제일 먼저 — 레플리카별로 갈라 본다

    Redis 연결은 백엔드 레플리카마다 따로 맺는다. 한 레플리카의 연결만 죽으면 그 레플리카로 간 요청만 실패해서, 전체로 보면 "일부 요청만 간헐적으로 500"처럼 보인다. 에러 로그를 레플리카(컨테이너 그룹 이름) 기준으로 나눠서, 한 곳에만 몰려 있는지 먼저 본다.

    1. 증상으로 원인 가르기¶

    보이는 것 뜻
    레플리카 하나에만 Command timed out after N 이 연속, 다른 레플리카는 정상 그 레플리카의 연결 하나가 조용히 끊긴 것(half-open). Redis 서버 문제가 아니다
    모든 레플리카에서 동시에 타임아웃 Redis 서버 또는 공통 경로 문제 — Redis 서버 지표(부하·연결 수·복제 상태)부터
    한참 뒤 NativeIoException: ... Connection timed out(-110) 한 줄 후 회복 커널이 재전송을 포기해 그제야 연결을 닫고 재연결한 것
    같은 순간 DB 풀에도 Failed to validate connection … ORA-17008 이 두 레플리카에서 찍힘 Redis 문제가 아니라 모든 연결이 함께 끊긴 순간 절단이다 → 커넥션 풀 고갈 진단 §3 정정 박스

    half-open 이란: 서버는 이미 연결을 잃었는데(또는 경로 중간에서 패킷이 사라지는데) 클라이언트는 그걸 모르는 상태다. 클라이언트가 끊김을 알아챌 장치가 없으면 죽은 소켓에 계속 쓰고, 리눅스 기본값으로는 재전송을 포기할 때까지 약 15분 걸린다. 그동안 그 연결을 쓰는 요청은 전부 명령 타임아웃만큼 기다린 뒤 실패한다.

    Redis 서버 쪽에서 보면 "연결 수가 하나 줄었다가 약 15분 뒤 돌아옴"으로 나타나고, 부하·복제 상태는 정상이다.

    2. 지금 들어가 있는 방어 — RedisClientConfiguration¶

    config/session/RedisClientConfiguration 이 Spring Boot 자동설정의 Lettuce 클라이언트에 다음을 얹는다(PR #181).

    설정 값 효과
    TCP_USER_TIMEOUT 30초 보낸 데이터에 30초 동안 응답이 없으면 커널이 연결을 닫는다 → Lettuce 가 바로 재연결
    TCP keepalive 30초 유휴 후 10초 간격 조용한 연결이 끊긴 것도 찾아낸다
    명령 타임아웃 10초(기본) 문제 구간에 들어온 요청이 60초가 아니라 10초 만에 실패한다

    로컬 재현(Redis 컨테이너에서 양방향 패킷 DROP + 서버측 CLIENT KILL)으로 잰 값:

    이 설정 없음(종전) 이 설정 있음
    요청 실패까지 60초 10초
    끊김 감지 — 요청이 오가는 중 100초 지나도 감지 못 함(약 15분) 30.5초
    끊김 감지 — 유휴 중 — 37.3초
    경로 회복 후 재연결 — 0.3~1.5초

    끊김 자체를 막지는 않는다

    "모르는 채 15분"을 "30~40초"로 줄일 뿐이다. 그 사이 그 레플리카로 들어온 요청은 여전히 실패한다(10초 만에). 끊김의 원인은 따로 봐야 한다. 2026-09-30 이후 사례는 Redis 를 Private Endpoint 로 옮긴 뒤에도 DB 연결과 같은 초에 끊겨, 원인이 Redis 경로가 아니라 백엔드 컨테이너 환경 쪽으로 보인다(Infra #75).

    리눅스 epoll 에서만 적용된다

    TCP_USER_TIMEOUT 과 keepalive 세부값은 Netty 네이티브 epoll 전송에서만 먹는다. 운영 컨테이너는 epoll 을 쓴다(사건 로그의 io.netty.channel.unix.Errors$NativeIoException 이 증거). epoll 이 없는 환경(로컬 Windows 등)에선 Lettuce 가 Cannot apply TCP User Timeout options ... 경고만 남기고 종전처럼 동작한다. 운영 로그에 이 경고가 보이면 방어가 꺼져 있는 것이다.

    3. 값을 바꾸고 싶을 때¶

    • 명령 타임아웃: spring.data.redis.timeout(env SPRING_DATA_REDIS_TIMEOUT)을 주면 코드 기본값 10초보다 우선한다.
    • 연결 타임아웃: spring.data.redis.connect-timeout 을 주면 그대로 반영된다(소켓 옵션을 얹을 때 옮겨 담는다).
    • TCP_USER_TIMEOUT·keepalive 값은 코드 상수다(RedisClientConfiguration). 명령 타임아웃보다 너무 짧게 잡으면 느린 명령 도중 연결이 끊길 수 있다.
