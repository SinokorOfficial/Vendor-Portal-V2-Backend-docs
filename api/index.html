    API 개요 · 규칙¶

    VP 백엔드의 HTTP API 공통 규칙을 정리한다. 응답 포맷(ResponseVo/ResponseErrorVo), 예외→응답 변환 파이프라인, 공개 엔드포인트(인증 면제) 규칙, 그리고 파트너 외부 API(/api/partner/**)를 다룬다. 모든 내용은 실제 소스 기준이며 인용은 상대경로:라인 형식이다.

    1. 정상 응답 포맷 (ResponseVo)¶

    대부분의 @RestController 메서드는 ResponseVo<T>를 반환한다. 데이터 캐리어는 DMap이고, 빌더로 조립한다.

    필드 타입 설명
    code String 응답 코드. 빈 값이면 기본 "200"
    message String 응답 메시지 (선택)
    data T 응답 데이터(DMap, List, String 등)
    traceId String Trace.getId() 분산 추적 ID

    기본값 처리는 생성자에서 일어난다 — code가 비어 있으면 "200"으로 채운다.

    // src/main/java/com/sinokor/vp/core/vo/ResponseVo.java:18-23
public ResponseVo(T data, String message, String code) {
    this.data = data;
    this.message = message;
    this.code = StringUtils.hasText(code) ? code : "200";
    this.traceId = Trace.getId();
}

    빌더 사용:

    // 데이터 응답 (PartnerController 예)
return ResponseVo.of(resultMap).build();          // code/message 생략 → code="200"

// 빈 응답 (로그아웃 핸들러 예)
return ResponseVo.of().build();
    • of(data) → ResponseVoBuilder<T>, of() → ResponseVoBuilder<Void> (ResponseVo.java:25-31).
    • 빌더 메서드는 message(...), code(...), build()만 존재한다 (ResponseVo.java:42-54).

    Note

    ResponseVo에는 message/code 기본값이 없다(생성 시 code만 "200"으로 보정). message를 지정하지 않으면 JSON에 null로 직렬화된다.

    2. 오류 응답 포맷 (ResponseErrorVo)¶

    예외 발생 시 JSON 응답은 ResponseErrorVo로 직렬화된다.

    필드 타입 설명
    code String 오류 코드. 빈 값이면 기본 "500" (ResponseErrorVo.java:25-26)
    type String 예외 클래스 simpleName (ResponseErrorVo.java:46)
    unknown boolean 인지 불가(예상 못한) 오류 여부
    message String 변환된 오류 메시지
    errDiv String 오류 구분 코드(아래 변환자 표 참고)
    traceId String Trace.getId() 
    {
  "code": "500",
  "type": "WebServiceException",
  "unknown": false,
  "message": "에러 메시지",
  "errDiv": "01",
  "traceId": "..."
}

    Warning

    errDiv는 "WEB"/"SERVICE"/"SYSTEM" 같은 라벨이 아니라 숫자 코드 문자열이다 — WebException="01", 그 외(인증/IO/일반)="02". 변환자 구현(*Translator.java)에서 확인됨.

    3. 예외 → 응답 변환¶

    전역 예외 처리는 GlobalHandlerExceptionResolver(스프링 MVC AbstractHandlerMethodExceptionResolver 상속)가 담당한다. 빈 등록은 HandlerExceptionConfiguration에서 이뤄진다.

    변환 흐름¶

    flowchart TD
    EX[Controller에서 Exception 발생] --> R[GlobalHandlerExceptionResolver.doResolveHandlerMethodException]
    R --> T["errorTranslators.stream().filter(supports).findFirst()"]
    T --> H[GlobalExceptionHandler.handle]
    H --> A{Accept 헤더에 text/html 포함?}
    A -- 예 --> V["ModelAndView (error 뷰, errDiv/unknown/message 모델)"]
    A -- 아니오 --> J["ResponseErrorVo (status 세팅 후 JSON)"]

    핵심 코드(GlobalHandlerExceptionResolver.java:188): 등록된 변환자 중 supports(exception.getClass())가 처음으로 참인 것을 findFirst().get()으로 고른다.

    // GlobalHandlerExceptionResolver.java:188
HttpErrorResponseTranslator translator =
    errorTranslators.stream().filter(t -> t.supports(exception.getClass())).findFirst().get();

    응답 분기(GlobalHandlerExceptionResolver.java:260-286): Accept에 text/html이 있으면 error 뷰(viewName())로, 아니면 response.setStatus(...) 후 ResponseErrorVo를 @ResponseBody로 반환한다.

    Note

    오류 응답에는 응답 헤더로 오류 코드가 함께 실린다 — writeErrorCodeService.getErrorHeader()/getErrorValue(...)로 채워진다(GlobalHandlerExceptionResolver.java:190-192). 헤더 이름·값은 WriteErrorCodeService 구현체에 의존한다.

    변환자 등록 순서와 매핑¶

    변환자는 등록 순서대로 매칭되며, 먼저 매칭된 것이 선택된다(findFirst). 등록 순서는 다음과 같다(HandlerExceptionConfiguration.java:55-60).

    순서 변환자 supports 대상 HTTP 상태 errDiv unknown
    1 WebExceptionTranslator WebException 계열 409 CONFLICT 01 false
    2 AuthenticationExceptionTranslator AuthenticationException 계열 401 UNAUTHORIZED 02 false
    3 ClientAbortExceptionTranslator MultipartException(MaxUploadSizeExceededException 제외) · ClientAbortException 400 BAD_REQUEST 02 true
    4 IOExceptionTranslator IOException 계열 500 INTERNAL_SERVER_ERROR 02 true
    5 ExternalServiceExceptionTranslator ExternalServiceException 502 BAD_GATEWAY 02 true
    6 JavaExceptionTranslator 모든 예외(supports가 항상 true) 500 INTERNAL_SERVER_ERROR 02 true

    근거: WebExceptionTranslator.java:16-33, AuthenticationExceptionTranslator.java:20-52, ClientAbortExceptionTranslator.java:23-79, IOExceptionTranslator.java:18-40, ExternalServiceExceptionTranslator.java:14-38, JavaExceptionTranslator.java:10-32.

    • ClientAbortExceptionTranslator는 원인 체인에 InvalidContentTypeException(멀티파트 계약 위반)이 있으면 MSG000431, 그 외 절단은 MSG000429로 응답한다(ClientAbortExceptionTranslator.java:52-58).
    • ExternalServiceExceptionTranslator는 MSG000430(SIPG 등 외부 서버 통신 불가) 전용 메시지로 응답한다(ExternalServiceExceptionTranslator.java:31-33).

    Warning

    JavaExceptionTranslator.supports(...)는 항상 true를 반환하므로(JavaExceptionTranslator.java:11) 마지막 폴백이다. 따라서 더 구체적인 변환자는 반드시 그 앞 순서에 등록되어야 한다. 같은 이유로 ClientAbortException은 IOException의 하위지만 ClientAbortExceptionTranslator(3번)가 IOExceptionTranslator(4번)보다 먼저 등록되어 400으로 처리되고, 나머지 IOException 계열은 500으로 처리된다.

    메시지 변환은 AbstractTypedHttpErrorResponseTranslator.translateMessage(...)가 용어사전(CurrentLocaleMessageSource)을 통해 수행한다. 예: 인증 실패는 UsernameNotFoundException/BadCredentialsException 등 종류별로 메시지를 분기한다(AuthenticationExceptionTranslator.java:30-46).

    예외 계층(소스 확인분)¶

    RuntimeException
├── WebException (writable, status=409 기본)   core/web/exception/core/WebException.java
│   ├── WebServiceException                    core/web/exception/WebServiceException.java
│   └── WebControllerException
└── ExternalServiceException (외부 연동 통신 실패, 502)   core/web/exception/core/ExternalServiceException.java
    ※ EirService 등 SIPG HTTP 호출 실패 시 IOException을 감싸 던진다

AuthenticationException (Spring Security)
├── JwtAuthenticationException                 core/web/exception/JwtAuthenticationException.java
└── LoginAuthenticationException               core/web/exception/LoginAuthenticationException.java

    WebServiceException.message("...") 정적 팩토리로 빌더를 얻는다(WebServiceException.java:13).

    4. 공개 엔드포인트(인증 면제) 규칙¶

    인증 면제 경로는 Java 설정이 아니라 application.yaml의 security.request-permit-all-mappings에 선언한다. SecurityProperty(@ConfigurationProperties(prefix="security"))가 바인딩한다(SecurityProperty.java:14-37).

    WebSecurityConfiguration.securityFilterChain(...)이 이 매핑을 순회하며 permitAll()을 부여하고, 나머지(/**)는 모두 authenticated()로 잠근다.

    // WebSecurityConfiguration.java:42-49
securityProperty.getRequestPermitAllMappings().forEach(mapping ->
    authorize.requestMatchers(HttpMethod.valueOf(mapping.getMethod()), mapping.getUrls()).permitAll());
authorize.requestMatchers("/**").authenticated();

    규칙 요약:

    • 매핑은 method(GET/POST 등) + urls(Ant 패턴 배열) 단위다.
    • 정적 자원은 Security 자체를 우회한다 — WebSecurityCustomizer가 ^/.+[.](html|js|css|ico|png|jpg|jpeg|gif|font|woff|woff2)$ 정규식 매칭 요청을 ignoring() 처리(WebSecurityConfiguration.java:33-35).
    • CORS/CSRF는 비활성화되어 있다 — cors(c -> c.disable()), csrf(c -> c.disable()) (WebSecurityConfiguration.java:40).

    현재 application.yaml.example 기준 공개 경로 일부(application.yaml.example:86-108):

    security:
  request-permit-all-mappings:
    - method: GET
      urls:
        - ${security.login-page-url}   # /login
        - /api/file/**
        - /api/partner/**
        - /api/eir/**                  # 테스트용. 이후 삭제 예정 주석
        # ... /jsp/**, /test/**, /application/health 등
    - method: POST
      urls:
        - ${security.login-url}         # /api/login
        - /api/auth/**
        - /api/partner/**
        - /api/eir/**
        # ... /api/code/selectCorpCode 등

    Note

    /api/eir/**는 yaml에 "신규 EIR 발급 테스트 관련. 테스트 이후 삭제" 주석이 달려 있다. 운영 반영 전 정리 여부를 확인하라.

    5. 인증 흐름 (로그인 / JWT / 로그아웃)¶

    로그인 — POST /api/login (공개)¶

    엔드포인트는 컨트롤러가 아니라 시큐리티 필터(LoginAuthenticationProcessingFilter)가 가로챈다. 매처는 security.login-url(/api/login)로 설정된다(WebSecurityBeansConfiguration.java:80).

    요청 본문은 JSON이다(폼 인코딩 아님). 필터가 Content-Type을 검사하며 application/json이 아니거나 본문 길이가 0이면 인증을 시도하지 않는다.

    // LoginAuthenticationProcessingFilter.java:29-37
if (contentType == null || !contentType.contains("application/json")) return null;
if (request.getContentLength() <= 0) return null;

    본문에서 아이디/비밀번호를 읽는 키는 설정값이다 — usernameParameter=security.username(기본 p), passwordParameter=security.password(기본 c) (WebSecurityBeansConfiguration.java:192-193, application.yaml.example:83-84). 즉 본문은:

    { "p": "사용자ID", "c": "비밀번호" }

    LoginUserAttemptAuthenticationService가 본문을 파싱해 GuestAuthentication(userId, password)를 만든다(LoginUserAttemptAuthenticationService.java:40-47).

    인증 체인(WebSecurityBeansConfiguration.java:140-145): LoginUserDaoAuthenticationProvider → LoginSuccessfulAuthenticationProvider. 비밀번호 인코더는 BCryptPasswordEncoder(WebSecurityBeansConfiguration.java:199-201). 마스터 로그인은 환경변수 MASTER_PASSWORD로 제어된다(소스 정책 참고).

    flowchart LR
    REQ["POST /api/login (JSON p/c)"] --> F[LoginAuthenticationProcessingFilter]
    F --> S[LoginUserAttemptAuthenticationService]
    S --> AM[LoginAuthenticationManager]
    AM --> DAO[LoginUserDaoAuthenticationProvider]
    DAO --> OK[LoginAuthenticationSuccessHandler]
    OK --> SESS["세션 영속 (Redis: SINOKORSESSION)"]

    성공 응답: LoginAuthenticationSuccessHandler가 HTTP 200으로 인증 객체(Authentication)를 직렬화해 본문에 쓴다(LoginAuthenticationSuccessHandler.java:20-29, AbstractAuthenticationSuccessBodyProcessHandler.java:24-30). 즉 로그인 성공 본문은 ResponseVo 래퍼가 아니라 인증 객체 직렬화 결과다.

    TODO: 클라이언트가 받는 정확한 필드(예: userId/corpCd/토큰 노출 여부)는 직렬화 대상 Authentication 구현(LoginUserAuthentication)에서 확인 필요.

    세션은 Redis로 영속된다 — Security 6 기본이 세션 비저장이라 HttpSessionSecurityContextRepository를 명시 설정해 레거시 동작을 복원했다(WebSecurityBeansConfiguration.java:86-89). 세션 store는 spring.session.store-type: redis, 타임아웃 7200초(application.yaml.example:59-63).

    실패 응답: DelegatingHandlerExceptionResolverAuthenticationFailureHandler가 위 예외 변환 파이프라인으로 위임하므로, 인증 실패는 401 + ResponseErrorVo(errDiv="02")로 나간다.

    JWT — 후속 API 호출¶

    JwtAuthenticationFilter(OncePerRequestFilter)가 BasicAuthenticationFilter 위치에 배치된다(WebSecurityConfiguration.java:55). 토큰은 Authorization 헤더 또는 ?token 쿼리 파라미터로 받는다.

    // JwtAuthenticationFilter.java:38-47
String token = request.getHeader(HttpHeaders.AUTHORIZATION);
if (token == null) token = request.getParameter("token");   // 헤더 없으면 ?token
// ...
token = token.replaceFirst("bearer ", "");                    // 접두사 제거 (소문자 "bearer ")
new GuestAuthentication(null, token, request.getHeader(X_FORWARDED_FOR));

    Warning

    접두사 제거는 replaceFirst("bearer ", "")로 소문자 bearer 리터럴만 제거한다(JwtAuthenticationFilter.java:22,46). 대문자 Bearer 접두사는 그대로 남으므로 토큰 형식에 주의.

    검증은 JwtVerifyAuthenticationProvider → JwtSwitchingLoginUserAuthenticationProvider → LoginSuccessfulAuthenticationProvider 체인(WebSecurityBeansConfiguration.java:148-154). 서명은 HMAC256, 시크릿은 security.jwt-hmac256-secret(JwtIssueService.java:23-25, application.yaml.example:85). 토큰이 없으면 필터는 그냥 통과시키고(chain.doFilter) 인증은 세션/시큐리티 컨텍스트에 의존한다.

    발급 토큰 클레임: 표준(jti/sub/aud/iss/iat/nbf/exp)에 더해 커스텀 클레임 userId, corpCd(필요 시 ssoCustCd, systemDiv, reqOptr*)를 담는다(JwtIssueService.java:79-126).

    로그아웃 — POST /api/logout (인증 필요)¶

    WebSecurityConfiguration.java:51-54에서 logoutUrl=security.logout-url(/api/logout), 성공 핸들러 LogoutSuccessBodyProcessorHandler, invalidateHttpSession(true)로 구성된다. 핸들러는 HTTP 200으로 빈 ResponseVo.of().build()를 반환한다(LogoutSuccessBodyProcessorHandler.java:34-38).

    6. 파트너 외부 API (/api/partner/**)¶

    수리비 면제 EIR(전자인수도증) 취소·파일 다운로드를 파트너(포탈/EBIZ)에 노출하는 공개 API다. 컨트롤러는 PartnerController(@RequestMapping("/api/partner"), @RestController), 의존성은 PartnerService/EirService/FileDataService(PartnerController.java:28-38). 경로 전체가 공개(permit-all)다.

    메서드 경로 입력 반환
    getToken POST /api/partner/getToken 없음 String (SIPG ESB 토큰)
    getCancelEir GET /api/partner/getCancelEir @RequestBody DMap(COMP_CD, BK_NO) ResponseVo<DMap> (RESULT)
    cancelEir POST /api/partner/cancelEir @RequestBody DMap(COMP_CD, BK_NO) ResponseVo<DMap> (MSG)
    download GET /api/partner/download @RequestParam COMP_CD,HBLNO,MNGT_NO,CNTR_NO ZIP 스트림
    downloadAll GET /api/partner/downloadAll @RequestParam COMP_CD,HBLNO,MNGT_NOS ZIP 스트림

    근거: PartnerController.java:40-214.

    Warning

    getToken은 ResponseVo가 아니라 순수 String 토큰을 반환한다(PartnerController.java:41-54). 또 getCancelEir/cancelEir는 @RequestBody DMap에서 COMP_CD/BK_NO만 사용한다(PartnerController.java:58-82). download는 MNGT_NO+CNTR_NO, downloadAll은 MNGT_NOS(쉼표 구분, 각 항목 MNGT_NO-CNTR_NO)를 쓴다(PartnerController.java:124,168-171,181-184).

    EIR 취소 처리(cancelEir) 요지¶

    1. partnerService.getCancelEir(param)로 취소 대상 EIR 목록 조회(PartnerController.java:85).
    2. 대상이 있으면 eirService.getValidTokenNew(compCd)로 토큰 획득(Redis 토큰 관리)(:92).
    3. 항목별로 eirService.setJson(...) → eirService.sendSIPGNew(...) 전송 → eirService.setEirResponse(...)로 응답 매핑(:102-109).
    4. 결과 메시지 목록을 resultMap.put("MSG", resultMsg)로 담아 ResponseVo.of(resultMap).build() 반환. 대상이 없으면 "There is no EIR to cancel."(:115-120).

    파일 다운로드¶

    • 응답은 application/zip + Content-Disposition: attachment로 스트리밍한다(PartnerController.java:139-140, 176-177).
    • download: NAS 파일 목록(fileService.fileDownloadNasList)을 ZIP으로 묶어 내려준다(:137-164).
    • downloadAll: MNGT_NOS를 쉼표로 분해하고 각 항목을 -로 MNGT_NO/CNTR_NO로 쪼개 일괄 처리(:171-211).

    API 호출 로그¶

    각 메서드는 호출 시 partnerService.insertCallApiLog(apiCode, channel, description)로 기록을 남긴다. 코드/채널 예:

    partnerService.insertCallApiLog("EIR001", "PORTAL", "");                       // getToken
partnerService.insertCallApiLog("EIR002", "PORTAL", "B/L No. : " + bkNo);      // cancelEir
partnerService.insertCallApiLog("API001", "EBIZ", "...");                      // download
partnerService.insertCallApiLog("API002", "EBIZ", "...");                      // downloadAll

    근거: PartnerController.java:45,95,132,174.
