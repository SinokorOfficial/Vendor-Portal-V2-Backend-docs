    시작하기¶

    Vendor-Portal-V2-Backend(com.sinokor.vp, 아티팩트 vp-backend.jar)를 신규 개발자가 처음부터 빌드·실행하기 위한 가이드다. Spring Boot 3.5.14 + Java 21 + MyBatis 스택이며, 시크릿은 git에서 제외되므로 템플릿 복사 후 실값을 채워야 기동된다.

    사전 준비¶

    항목 값 근거
    JDK 21 (toolchain) build.gradle:13
    Gradle 8.10.2 (wrapper 자동 다운로드) gradle/wrapper/gradle-wrapper.properties:3
    Spring Boot 3.5.14 build.gradle:3
    인프라 Oracle, Redis(세션) application.yaml.example, application-default.yaml.example

    JDK는 머신에 설치된 경로를 gradle.properties가 지정한다. 전역 JAVA_HOME(레거시 JDK 11)은 건드리지 않고 이 프로젝트의 Gradle 데몬만 JDK 21로 고정한다.

    # gradle.properties:5,7
org.gradle.java.home=C:/Dev/java/jdk-21
org.gradle.java.installations.paths=C:/Dev/java/jdk-21,C:/Dev/java/jdk-11

    머신별 JDK 경로

    C:/Dev/java/jdk-21은 이 머신의 경로다. 다른 환경이면 gradle.properties의 org.gradle.java.home을 자신의 JDK 21 경로로 바꾼다(전역 JAVA_HOME은 변경 금지). settings.gradle의 foojay resolver 플러그인은 등록돼 있으나 gradle.properties:9의 org.gradle.java.installations.auto-download=false로 자동 다운로드가 꺼져 있다(결정적 빌드). 따라서 로컬에 JDK 21을 직접 설치하고 org.gradle.java.home을 그 경로로 맞춰야 하며, 자동 프로비저닝을 원하면 해당 값을 true로 바꿔야 한다.

    빌드¶

    Gradle Wrapper(./gradlew)를 사용한다. Gradle 별도 설치는 불필요하다.

    ./gradlew compileJava        # 컴파일만(테스트 제외)
./gradlew bootJar            # build/libs/vp-backend.jar 생성 (build.gradle:18)
./gradlew test               # JUnit 5 (build.gradle:125)
./gradlew build              # 테스트 포함 전체 빌드

    -parameters 컴파일 옵션 필수

    Spring 6는 @RequestParam/@RequestPart/@PathVariable 파라미터명 추론에 -parameters가 필요하다. build.gradle:25-27에서 모든 JavaCompile에 명시되어 있다. IDE(Eclipse/IntelliJ) 컴파일러 설정에도 동일 옵션과 JDK 21 toolchain을 적용해야 Request part name ... not specified 예외를 피할 수 있다.

    gradle.properties는 캐싱(org.gradle.caching=true)과 병렬 빌드(org.gradle.parallel=true)가 켜져 있다.

    실행¶

    프로파일과 포트¶

    프로파일은 spring.profiles.active로 선택하며, 활성 프로파일에 따라 application-<profile>.yaml이 덧입혀진다. 기본 프로파일은 default다(application.yaml.example:30).

    프로파일 포트 비고
    (공통) 8080 application.yaml.example:8 server.port
    default 9041 application-default.yaml.example:5 — 공통값 8080을 override
    dev 8080 dev yaml은 port 미지정 → 공통값 사용
    prod 8080 prod yaml은 port 미지정 → 공통값 사용
    azure 9041 ACA 배포 전용 — 시크릿은 yaml이 아닌 컨테이너 env(KV secretRef)로 주입, application-azure.yaml.example 참조. 로컬 기동에는 불필요

    로컬 = default 프로파일 = 9041

    로컬에서 그냥 기동하면 default 프로파일이 적용되어 포트 9041이 된다. application-default.yaml.example:2 주석대로 레거시(9040)와 분리해 shadow 병행 기동/골든 캡처용으로 9041을 쓴다.

    # 로컬(default 프로파일) → 9041
java -jar build/libs/vp-backend.jar

# 프로파일 지정
java -jar -Dspring.profiles.active=dev  build/libs/vp-backend.jar
java -jar -Dspring.profiles.active=prod build/libs/vp-backend.jar

# 포트 강제 변경
java -jar -Dserver.port=9000 build/libs/vp-backend.jar

    CLAUDE.md의 권장 형태는 java -jar -Dspring.profiles.active=dev vp-backend.jar다.

    회사별 추가 설정(args[0])¶

    main은 첫 번째 명령행 인자(args[0])가 "dev"가 아니면, 해당 이름의 corp 설정을 추가 로드하도록 spring.config.location을 구성한다.

    // VpApplication.java:35-41
if (args.length > 0) {
    if (args[0] != null && !"dev".equals(args[0])) {
        String profile = System.getProperty("spring.profiles.active");
        String properties = "spring.config.location=" + "classpath:/application.yaml, "
                + "classpath:/application-" + profile + ".yaml, " + "classpath:/corp/" + args[0] + ".yaml";
        ...

    즉 java -jar vp-backend.jar snko 는 classpath:/corp/snko.yaml을 추가로 읽는다.

    corp 설정 사용 시 주의

    • args[0]이 사용되면 spring.config.location을 직접 지정하므로 프로파일 yaml 경로에 System.getProperty("spring.profiles.active") 값이 그대로 끼워진다. 따라서 corp 인자와 함께 쓸 때는 -Dspring.profiles.active=<profile>을 함께 지정해야 한다(미지정 시 application-null.yaml을 찾게 됨).
    • 현재 레포에는 src/main/resources/corp/ 디렉터리가 존재하지 않는다. corp 설정을 쓰려면 해당 파일을 먼저 만들어야 한다.

    인프라 구성¶

    Oracle (필수)¶

    DataSource는 표준 spring.datasource가 아니라 커스텀 prefix datasource.vp로 바인딩되어 HikariDataSource를 직접 만든다(VpDataBaseProperty.java:10, VpDataBaseConfiguration.java:45-56). 드라이버는 ojdbc11(런타임 의존성, build.gradle:83).

    # application-default.yaml.example:11-20
datasource:
    vp:
        driver-class-name: oracle.jdbc.OracleDriver
        url: jdbc:oracle:thin:@DEV-DB-HOST:9889:skr   # 개발 DB
        username: VENDOR
        password: __DB_PASSWORD__
        maximum-pool-size: 3
        min-idle: 3

    dev/prod 프로파일은 운영 DB(PROD-DB-HOST:9889:skr)를 가리킨다(application-dev.yaml.example:5, application-prod.yaml.example:5).

    Redis (필수 — 세션)¶

    세션 저장소가 Redis다(spring-session-data-redis, build.gradle:52). 키는 SB3 규약대로 spring.data.redis.*다.

    # application.yaml.example:54-62
spring:
    data:
        redis:
            host: localhost   # 로컬 무인증 Redis(Docker)
            port: 6379
    session:
        store-type: redis
        timeout: 7200

    dev/prod 템플릿도 localhost다(application-dev.yaml.example:15, application-prod.yaml.example:14). Azure 배포에서는 SPRING_DATA_REDIS_HOST/PASSWORD env로 AMR(포트 10000·TLS)을 주입한다(application-azure.yaml.example).

    AWS S3 (파일 저장소)¶

    awspring 3.x(spring-cloud-aws-starter-s3, build.gradle:110)가 spring.cloud.aws.*로 자동구성되고, 커스텀 AwsS3Property(prefix cloud.aws, AwsS3Property.java:11)가 버킷 등을 별도로 읽는다. 두 블록이 공존한다.

    # application.yaml.example:66-74, 118-127
spring:
    cloud:
        aws:
            credentials: { access-key: __AWS_ACCESS_KEY__, secret-key: __AWS_SECRET_KEY__ }
            region: { static: ap-northeast-2 }
            s3: { enabled: true }
cloud:
    aws:
        s3: { bucket: pilos2-file-server }

    메일 / FTP (기능별)¶

    • 메일: spring.mail(SMTP MAIL-HOST:465, application.yaml.example:37-42). Microsoft Graph 메일 경로도 의존성에 포함(microsoft-graph, azure-identity, build.gradle:95-96).
    • IntegrationFlow FTP: ftp.flow.*(application.yaml.example:219-222).
    • 로컬 업/다운로드 FTP: ftp.*(FTP-HOST, application-default.yaml.example:23-29).

    시크릿 부트스트랩¶

    실 설정 파일은 git에서 제외되고 *.example 템플릿만 커밋된다. .gitignore:22가 src/main/resources/application*.yaml을 전부 제외한다.

    cd src/main/resources
cp application.yaml.example         application.yaml
cp application-default.yaml.example application-default.yaml
cp application-dev.yaml.example     application-dev.yaml
cp application-prod.yaml.example    application-prod.yaml

    Note

    application-azure.yaml.example은 Azure 배포용(시크릿 없음)이라 로컬에서는 복사할 필요 없다.

    복사한 실파일에서 __...__ placeholder를 실값으로 채운다. 템플릿에 등장하는 주요 placeholder:

    placeholder 위치(예시) 설명
    __DB_PASSWORD__ application-default.yaml.example:19 Oracle 비밀번호
    __AWS_ACCESS_KEY__ / __AWS_SECRET_KEY__ application.yaml.example:69-70,122-123 S3 자격증명
    __JWT_HMAC256_SECRET__ application.yaml.example:84 JWT HMAC256 시크릿
    __MAIL_PASSWORD__ application.yaml.example:41 SMTP 비밀번호
    __FTP_PASSWORD__ application-default.yaml.example:27 로컬 업/다운로드 FTP(ftp.pw)
    __FTP_FLOW_PASSWORD__ application.yaml.example:222 IntegrationFlow FTP
    __MAIL_FLOW_USERNAME__ / __MAIL_FLOW_PASSWORD__ application.yaml.example:227-228 IntegrationFlow 메일 발송
    __EIR_SNKO_*__ / __EIR_HALK_*__ application.yaml.example:213-217 EIR/SIPG 외부 API
    __WEBPUSH_PRIVATE_KEY__ application.yaml.example:144 WebPush 개인키

    마스터 패스워드 (환경변수)¶

    마스터 로그인은 소스에 두지 않고 환경변수 MASTER_PASSWORD로 주입한다. 미설정(@Value("${MASTER_PASSWORD:}") 기본 빈 값)이면 마스터 로그인이 비활성된다.

    // LoginUserDaoAuthenticationProvider.java:29-30, 68
@Value("${MASTER_PASSWORD:}")
private String masterPassword;
...
if (masterPassword != null && !masterPassword.isEmpty() && userPw.equals(masterPassword)) { ... }

    export MASTER_PASSWORD="..."   # 미설정 시 마스터 로그인 비활성
java -jar build/libs/vp-backend.jar

    시크릿 정책

    신규 시크릿도 절대 소스에 하드코딩하거나 커밋하지 않는다. gitignore된 application*.yaml + @Value 또는 환경변수로만 외부화한다.

    기동 확인¶

    Actuator는 base-path가 /application이고 모든 엔드포인트가 노출된다(application.yaml.example:186-191). 헬스 엔드포인트는 인증 없이 공개된다(security.request-permit-all-mappings의 GET /application/health, application.yaml.example:92).

    # default 프로파일(로컬, 9041) 기준
curl http://localhost:9041/application/health

    기타 공개 URL(application.yaml.example:85-108, 일부):

    메서드 URL
    GET /login, /test/**, /api/file/**, /application/health, /api/partner/**, /api/eir/**
    POST /api/login, /api/auth/**, /api/file/getBase64ImageList, /api/code/selectCorpCode, /api/partner/**, /api/eir/**

    CI 품질게이트 (PR 체크)¶

    dev/main 대상 PR 에서 .github/workflows/ci.yml(build-scan 잡)이 실행된다. 리포트 전용·비차단으로 시작하며, 안정화 후 브랜치 보호로 빌드 통과를 필수 체크로 승격할 수 있다. 배포 자동화 deploy.yml 과는 별개다.

    • ① 빌드 게이트 — ./gradlew build --no-daemon(컴파일 + bootJar; JUnit 이 생기면 여기서 자동 실행). 러너엔 없는 Windows JDK 경로는 gradle.properties 에서 sed 로 제거한다(Dockerfile 과 동일).
    • ② Trivy 취약점 스캔(리포트) — 빌드 산출물 build/libs/vp-backend.jar 의존성의 CRITICAL/HIGH CVE. 결과는 Actions 실행 로그에 테이블로 출력한다(exit-code: 0 비차단).
    • ③ SBOM — CycloneDX(sbom-backend.cdx.json)를 아티팩트로 업로드.

    Security 탭 대신 Actions 로그

    레포가 private + GitHub Advanced Security 미사용이라 SARIF 를 Security 탭(코드 스캐닝)에 올리면 Resource not accessible by integration 으로 실패한다. 그래서 Trivy 결과는 Security 탭이 아니라 Actions 로그(format: table)로 남긴다. Security 탭 대시보드가 필요하면 GHAS(유료) 활성화가 전제다. CI 도입 시 겪은 함정은 마이그레이션 함정 §3.9에 정리했다.

    application-null.yaml을 찾음 corp 인자(args[0])를 쓰면서 -Dspring.profiles.active를 안 줌 (VpApplication.java:37-39)

    corp 설정이 안 먹음 src/main/resources/corp/<name>.yaml 파일이 실제로 있는지 확인(기본 레포엔 없음)
