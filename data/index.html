    데이터 · MyBatis¶

    Vendor-Portal-V2 백엔드의 데이터 접근 계층은 MyBatis XML 매퍼 + @VpRepository DAO + DMap 결과 캐리어 조합으로 구성된다. JPA/타입 DTO를 도입하지 않고, 쿼리 결과를 모두 DMap(=HashMap<String,Object>)으로 받아 동적 키로 다룬다.

    전체 흐름¶

    flowchart LR
    SVC["@Service"] -->|DMap param| DAO["@VpRepository DAO 인터페이스"]
    DAO -->|MapperScan| XML["oracle/<module>/*-mapper.xml"]
    XML -->|"resultType=dmap"| MB[MyBatis]
    MB -->|HikariDataSource| ORA[(Oracle)]
    ORA -->|ResultSet| MB
    MB -->|"List&lt;DMap&gt; / DMap"| SVC

    DAO 마커: @VpRepository¶

    @Mapper가 아닌 전용 마커 어노테이션을 사용한다. 정의 자체는 메서드 없는 빈 어노테이션이다.

    @Target( ElementType.TYPE )
@Retention( RetentionPolicy.RUNTIME )
@Documented
public @interface VpRepository {}
    출처: src/main/java/com/sinokor/vp/config/annotation/VpRepository.java:5

    스캔은 VpDataBaseConfiguration의 @MapperScan이 담당한다. annotationClass로 이 마커만 골라 등록한다.

    @MapperScan(
    basePackages = "com.sinokor.vp",
    annotationClass = VpRepository.class
)
    출처: src/main/java/com/sinokor/vp/config/database/VpDataBaseConfiguration.java:30

    DAO 인터페이스는 마커를 붙이고 DMap/List<DMap>을 반환한다. 파라미터가 2개 이상이면 @Param으로 키를 명시한다.

    @VpRepository
public interface AdminDao {
    DMap selectUser(@Param("USER_ID") String USER_ID, @Param("CORP_CD") String CORP_CD);
    List<DMap> selectRoleId(@Param("USER_ID") String USER_ID, @Param("CORP_CD") String CORP_CD);
    void updateUser(DMap user);
}
    출처: src/main/java/com/sinokor/vp/admin/dao/AdminDao.java:10

    MyBatis 설정 (mybatis-config.xml)¶

    <settings>
    <setting name="cacheEnabled" value="true"/>
    <setting name="callSettersOnNulls" value="true"/>
    <setting name="jdbcTypeForNull" value="VARCHAR"/>
</settings>
<typeAliases>
    <typeAlias alias="dmap" type="com.sinokor.vp.core.vo.DMap"/>
</typeAliases>
    출처: src/main/resources/mapper/mybatis-config.xml:4

    설정 값 의미
    cacheEnabled true MyBatis 2차 캐시 활성화
    callSettersOnNulls true null 컬럼도 결과 Map에 키로 채움(키 누락 방지)
    jdbcTypeForNull VARCHAR null 파라미터 바인딩 시 기본 JDBC 타입
    typeAlias dmap …core.vo.DMap 매퍼에서 resultType="dmap"로 사용

    callSettersOnNulls와 DMap

    DMap은 HashMap 기반이라 컬럼 값이 null이면 키 자체가 빠질 수 있다. 이 설정으로 null 컬럼도 키가 보존되어, 후속 getString() 등이 안정적으로 동작한다.

    매퍼 XML 구조¶

    위치: src/main/resources/mapper/oracle/<module>/<Xxx>-mapper.xml. 매퍼 로딩 경로는 yaml로 외부화돼 있다.

    mybatis:
    vp:
        config-path: classpath:mapper/mybatis-config.xml
        resources-sub-path: oracle
        param-count: 1000
        resources-path: classpath:mapper/${mybatis.vp.resources-sub-path}/**/*-mapper.xml
    출처: src/main/resources/application.yaml.example:111

    이 키들은 VpMybatisProperty(@ConfigurationProperties prefix="mybatis.vp")에 바인딩된다 — 필드 resourcesPath, configPath, paramCount. 출처: src/main/java/com/sinokor/vp/config/property/VpMybatisProperty.java:11

    실제 매퍼 예시(Admin-mapper.xml):

    <mapper namespace="com.sinokor.vp.admin.dao.AdminDao">
  <select id="selectUser" resultType="dmap">
    /* admin.dao.AdminDao.selectUser */
    SELECT A.USER_ID, A.USER_PWD, ...
      FROM TB_CMS_USER A
      LEFT JOIN TB_CMS_USER_CORP_MGT A1 ON A1.USER_ID = A.USER_ID
        <choose>
          <when test="CORP_CD != null and CORP_CD != ''">
            AND A1.CORP_CD = #{CORP_CD}
          </when>
          <otherwise>
            AND A1.MAIN_YN = 'Y'
          </otherwise>
        </choose>
     WHERE A.USER_ID = #{USER_ID}
  </select>
</mapper>
    출처: src/main/resources/mapper/oracle/admin/Admin-mapper.xml:3

    관례

    • namespace = DAO 인터페이스 풀 경로.
    • <select> id = DAO 메서드명(예: selectUser → selectUser()).
    • 모든 조회는 resultType="dmap".
    • 첫 줄에 /* 풀경로 */ 주석 — 로그에서 출처 식별용.
    • 파라미터는 #{KEY}(바인드), 동적 SQL은 <choose>/<when>/<if> 등 표준 태그.

    DMap 매핑 동작¶

    resultType="dmap"이면 MyBatis가 각 행을 DMap 인스턴스로 만들고, 컬럼명(Oracle 기본 대문자)을 키, 값을 값으로 넣는다. 단건은 DMap, 다건은 List<DMap>로 받는다.

    DMap은 타입드 getter를 제공한다(부분 발췌):

    public String getString(String key) { ... }        // null이면 "" 반환
public int getInt(String key) { ... }               // null/"" 이면 0
public Long getLong(String key) { ... }
public BigDecimal getBigDecimal(String key) { ... }
public Timestamp getTimestamp(String key) { ... }
public LocalDateTime getLocalDateTime(String key) { ... }  // Timestamp/String 모두 변환
public LocalDate getLocalDate(String key) { ... }
public DMap getMap(String key) { ... }
public List<DMap> getMapList(String key) { ... }
    출처: src/main/java/com/sinokor/vp/core/vo/DMap.java:14

    getter의 기본값 동작

    getString()은 null일 때 빈 문자열 "", getInt()/getLong()/getDouble()/getBigDecimal()은 null·빈문자일 때 0을 돌려준다(예외를 던지지 않음). null 여부를 구분해야 하면 containsKey()나 super.get()을 직접 써야 한다.

    사용 예:

    DMap row = ...;                              // 단건 select 결과
String userId = row.getString("USER_ID");
int failCnt   = row.getInt("LOGIN_FAIL_CNT");
List<DMap> roles = row.getMapList("ROLE_LIST");

    참고: LAST_LOGIN_TM 같은 컬럼은 매퍼에서 TO_CHAR(..., 'YYYY.MM.DD HH24:MI:SS')로 문자열 포맷되어 내려오는 경우가 있다(Admin-mapper.xml:21). 컬럼 타입은 매퍼 SQL을 확인할 것.

    PageHelper 페이징¶

    설정¶

    pagehelper:
    auto-dialect: true
    reasonable: true
    supportMethodsArguments: true
    pageSizeZero: true   # pageSize=0 → 전체조회 (레거시 동작 복원)
    출처: src/main/resources/application.yaml.example:158

    버전: pagehelper-spring-boot-starter 1.4.7(build.gradle:71). 레거시 1.2.3에서 올라왔다.

    pageSizeZero는 삭제 금지

    1.4.7부터는 pageSizeZero를 명시하지 않으면 pageSize=0일 때 빈 결과를 반환한다. 레거시(1.2.3)는 같은 입력에 전체조회였으므로, 동등성 유지를 위해 pageSizeZero: true가 필수다. 출처: application.yaml.example:162-163(주석)

    사용 패턴¶

    서비스에서 PageHelper.startPage()를 호출한 뒤 바로 DAO 조회를 실행한다. DAO 반환 타입은 com.github.pagehelper.Page<DMap>이며, 여기서 메타(getPages(), getTotal())를 꺼낸다.

    int currPage = param.getInt("CURR_PAGE");
int perPage  = param.getInt("PER_PAGE");
PageHelper.startPage(currPage, perPage);

Page<DMap> list = mdmNoticeDao.selectList( param );   // DAO 시그니처도 Page<DMap>
retMap.put("BOARD_GRID",  list);
retMap.put("PAGE_LENGTH", list.getPages());
retMap.put("PAGE_TOTAL",  list.getTotal());
    출처: src/main/java/com/sinokor/vp/mdm/other/service/MdmNoticeService.java:42 · DAO: …/mdm/other/dao/MdmNoticeDao.java:11

    PAGEHELPER_ROW_ID 누출 제거¶

    PageHelper 5.2+ 의 Oracle 페이징은 결과를 SELECT *, ROWNUM PAGEHELPER_ROW_ID로 감싼다. resultType이 Map(dmap)이면 이 합성 컬럼이 결과 키로 새어든다. 이를 ResultSetHandler 단계에서 제거해 레거시 응답과 동등하게 맞춘다.

    @Intercepts({
    @Signature(type = ResultSetHandler.class, method = "handleResultSets", args = { Statement.class })
})
public class PageHelperRowIdStripInterceptor implements Interceptor {
    private static final String PAGEHELPER_ROW_ID = "PAGEHELPER_ROW_ID";
    ...
    // 결과 Map의 PAGEHELPER_ROW_ID 키 제거(대소문자 무시)
}
    출처: src/main/java/com/sinokor/vp/core/mybatis/PageHelperRowIdStripInterceptor.java:23

    항목 값 근거

    JDBC URL datasource.vp.url(yaml, gitignore) VpDataBaseProperty.java:13
    드라이버 클래스 datasource.vp.driverClassName 동상

    application.yaml에 다음 Oracle 관련 키가 선언돼 있다.

    oracle:
    jdbc:
        J2EE13Compliant: true
    출처: src/main/resources/application.yaml.example:181

    Note

    oracle.jdbc.J2EE13Compliant를 직접 읽는 Java 코드는 소스에 없다(별도 @ConfigurationProperties 미존재). Oracle JDBC 드라이버가 인식하는 시스템 프로퍼티 성격의 호환 플래그로 보이며, 실제 적용 경로는 추가 확인이 필요하다.
