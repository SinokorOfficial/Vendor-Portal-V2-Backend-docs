    아키텍처 개요¶

    Vendor-Portal-V2 백엔드(vp-backend)는 Spring Boot 3.5 + Java 21 위에서 MyBatis(XML 매퍼)로 동작하는 다중 모듈 서블릿 애플리케이션이다. 타입 DTO/JPA 대신 DMap을 데이터 캐리어로 쓰고 응답은 ResponseVo로 통일하며, FTP·Mail·WebPush·HTTP 연동은 Spring Integration 플로우로, 실시간 알림은 STOMP WebSocket으로 처리한다.

    -parameters 강제

    Spring 6는 @RequestPart/@RequestParam 등의 파라미터명 추론에 -parameters 컴파일 옵션이 필요해 JavaCompile 전체에 강제 추가한다(build.gradle:25-27).

    부트스트랩 (VpApplication)¶

    VpApplication은 SpringBootServletInitializer를 상속하고, main에서 BouncyCastle 보안 제공자 등록 → SpringApplicationBuilder 구성 → PID 파일 기록 순으로 기동한다(VpApplication.java:30-44).

    • AutoConfiguration 제외: 커스텀 구현으로 대체하기 위해 4개를 제외한다 — MessageSourceAutoConfiguration, HttpMessageConvertersAutoConfiguration, ErrorMvcAutoConfiguration, JdbcRepositoriesAutoConfiguration(VpApplication.java:24-25).
    • 활성 어노테이션: @EnableConfigurationProperties(StorageProperties.class), @IntegrationComponentScan(VpApplication.java:26-27).
    • corp별 설정 주입: args[0]가 dev가 아니면 classpath:/corp/{args[0]}.yaml을 spring.config.location에 추가해 회사별 프로파일을 덧입힌다(VpApplication.java:35-41).
    • 스토리지 초기화: CommandLineRunner로 StorageService.init()을 1회 실행한다(VpApplication.java:47-50).

    모듈 레이아웃¶

    업무 도메인은 최상위 패키지로 평탄하게 나뉘며, 각 도메인은 controller / service / dao 3계층을 갖는다. config(부트/인프라 설정)와 core(공통 기반)가 횡단 토대를 이룬다.

    com.sinokor.vp/
├── admin/  api/  cfs/  cms/  crs/  csm/      # 업무 도메인
│   dsh/  eir/  fds/  mdm/  mvs/  vps/
│   └── {controller, service, dao}/          # 도메인별 3계층
├── config/                                   # 부팅·인프라 구성
│   ├── annotation/   # @VpRepository, @UpperSnakeCase
│   ├── aop/          # TraceAdvice, MybatisDaoMethodParameterAdvice
│   ├── database/     # DataSource·TxManager·SqlSessionFactory
│   ├── integration/  # ftp / http / mail / webpush 플로우
│   ├── property/     # @ConfigurationProperties 바인딩
│   ├── web/          # MVC·필터·시큐리티 설정
│   └── websocket/    # STOMP 브로커
└── core/                                     # 공통 기반
    ├── vo/           # DMap, ResponseVo, ResponseErrorVo
    ├── web/security/ # filter / provider / handler / entrypoint ...
    ├── web/exception, web/resolver, web/converter
    ├── mybatis/      # SqlSessionFactory 확장·PageHelper 후처리
    ├── storage/  ftp/  http/  mail/  template/  trace/  util/

    위 도메인 목록은 src/main/java/com/sinokor/vp/ 하위 디렉터리에서 확인했다. 매퍼 XML은 도메인별로 src/main/resources/mapper/oracle/<module>/*-mapper.xml에 둔다(매퍼 디렉터리: admin/api/cfs/cms/crs/csm/dsh/eir/fds/mdm/mvs/vms).

    레이어 흐름¶

    요청은 @RestController → @Service → @VpRepository DAO 인터페이스 → MyBatis XML 순으로 흐른다. DAO는 @Mapper가 아니라 커스텀 마커 @VpRepository만 단 인터페이스이고(config/annotation/VpRepository.java:8, admin/dao/AdminDao.java:10), VpDataBaseConfiguration의 @MapperScan(annotationClass = VpRepository.class)가 이를 스캔한다(config/database/VpDataBaseConfiguration.java:30-33).

    flowchart TD
    C["@RestController\n(ExtendBaseController 상속)"] --> S["@Service"]
    S --> D["@VpRepository DAO\n(인터페이스)"]
    D --> X["MyBatis XML\nmapper/oracle/&lt;module&gt;/*-mapper.xml"]
    X --> DS["HikariDataSource\n(p6spy 데코레이트)"]
    DS --> ORA[("Oracle / MSSQL")]
    S -. 응답 .-> R["ResponseVo.of(DMap).build()"]
    R --> C
    AOP1["TraceAdvice\n(@Around controller)"] -. traceId 생성 .-> C
    REDIS[("Redis\n세션 2h")] -. HttpSession .-> C
    • 데이터 캐리어 DMap: HashMap<String,Object> 확장에 getString/getInt/getBigDecimal/getTimestamp 등 타입드 게터를 제공한다(core/vo/DMap.java:14-60).
    • 응답 ResponseVo: code/message/data/traceId를 담는 제네릭 래퍼. ResponseVo.of(data).message(...).build() 빌더로 만들며, code 미지정 시 "200", traceId는 Trace.getId()로 채워진다(core/vo/ResponseVo.java:18-54).
    • DataSource/Tx/SqlSessionFactory: 모두 VpDataBaseConfiguration에서 @Primary 빈으로 직접 구성한다. Hikari autoCommit=false, p6spy가 BeanPostProcessor로 자동 래핑(VpDataBaseConfiguration.java:43-57). SqlSessionFactory에는 PageHelperRowIdStripInterceptor를 플러그인으로 끼워 Oracle 페이징이 흘리는 합성 컬럼 PAGEHELPER_ROW_ID를 제거한다(VpDataBaseConfiguration.java:66-86).

    보안 / 세션¶

    WebSecurityConfiguration이 단일 SecurityFilterChain을 구성한다(config/web/security/WebSecurityConfiguration.java:38-61).

    • 공개 경로: Java 코드가 아니라 application.yaml의 security.request-permit-all-mappings(method+urls 목록)를 읽어 permitAll()로 등록하고, 나머지 /**는 authenticated()로 막는다(WebSecurityConfiguration.java:42-49; 매핑 정의: application.yaml.example:86-108).
    • 정적 리소스: .html/.js/.css/... 확장자는 정규식 매처로 시큐리티 체인에서 제외(WebSecurityConfiguration.java:33-36).
    • 필터 배치: JwtAuthenticationFilter를 BasicAuthenticationFilter 위치에, LoginAuthenticationProcessingFilter를 UsernamePasswordAuthenticationFilter 위치에 끼운다(WebSecurityConfiguration.java:55-56).
    • 인증 제공자 체인: core/web/security/provider에 JWT 검증·로그인·마스터 로그인용 Provider들이 있다(JwtVerifyAuthenticationProvider, LoginUserDaoAuthenticationProvider, JwtSwitchingLoginUserAuthenticationProvider, LoginSuccessfulAuthenticationProvider 등).
    • 세션: Redis 저장(spring.session.store-type: redis), 타임아웃 7200초(2h)(application.yaml.example:59-63). JWT 시크릿은 security.jwt-hmac256-secret로 외부화(application.yaml.example:85).

    예외 처리¶

    ErrorMvcAutoConfiguration을 끄고 GlobalHandlerExceptionResolver(커스텀, AbstractHandlerMethodExceptionResolver 기반)가 전역 예외를 잡는다(core/web/resolver/GlobalHandlerExceptionResolver.java:66).

    • 예외별 HttpErrorResponseTranslator로 상태·메시지를 해석하고, Accept: text/html이면 Pebble 뷰를, 그 외엔 ResponseErrorVo를 직렬화해 반환한다(GlobalHandlerExceptionResolver.java:260-287).
    • 인증 사용자(LoginUser)의 userId를 에러 로그에 함께 기록한다(GlobalHandlerExceptionResolver.java:179-193).
    • 업무 예외 계층: WebControllerException, WebServiceException, JwtAuthenticationException, LoginAuthenticationException(core/web/exception/). 여기에 ExternalServiceException(외부 연동 실패 → 502, core/web/exception/core/, 번역기 ExternalServiceExceptionTranslator)과 LoginFailureReasonException(로그인 실패 사유 세분화, cause 체인)이 있다.
    • 번역기 등록 순서: ClientAbortExceptionTranslator·ExternalServiceExceptionTranslator는 각각 IOExceptionTranslator·JavaExceptionTranslator보다 먼저 등록된다(config/web/beans/HandlerExceptionConfiguration.java:55-60).

    외부 통합 (Spring Integration)¶

    config/integration/ 아래 4개의 IntegrationFlow가 메시징 게이트웨이로 외부 시스템과 연동한다.

    flowchart LR
    subgraph App["vp-backend"]
      direction TB
      MG1["MailSendGateway"] --> MC["mailSendChannel"]
      MG2["FtpGateway / FtpLsGateway"] --> FC["ftpTransferChannel"]
      MG3["WebPushGateway"] --> PC["webPushSendChannel"]
      MG4["HttpGateway"] --> HC["httpRequestChannel"]
    end
    MC --> SMTP["SMTP outboundAdapter\nMAIL-HOST:465"]
    FC --> FTP["FTP outboundAdapter\n(ulogitech)"]
    PC --> WP["WebPushOutboundGateway\n(VAPID)"]
    HC --> EXT["RestTemplate outboundGateway\n(외부 REST)"]
    플로우 게이트웨이 특징 근거
    Mail MailSendGateway.send(...) Mail.outboundAdapter, SMTP 465/SSL, HTML 본문 헤더 주입 config/integration/mail/MailFlowConfiguration.java:21-56
    WebPush WebPushGateway.send(DMap, DMap) WebPushOutboundGateway(pushService), send/receive 채널 분리 config/integration/webpush/WebPushFlowConfiguration.java:28-50
    HTTP HttpGateway.get/post(...) Http.inboundGateway/outboundGateway, 응답 DMap으로 추출 config/integration/http/HttpFlowConfiguration.java:45-122
    FTP FtpGateway / FtpLsGateway Ftp.outboundAdapter/outboundGateway, CachingSessionFactory config/integration/ftp/FtpFlowConfiguration.java:33-84

    FTP 플로우 비활성 상태

    FtpFlowConfiguration의 @Bean/@Gateway 어노테이션이 주석 처리돼 있어 FTP 플로우는 현재 비활성이다(FtpFlowConfiguration.java:32,44,57-73). 비밀번호는 ftp.flow.password로 외부화되어 있다(FtpFlowConfiguration.java:29).

    실시간 (WebSocket / STOMP)¶

    WebSocketConfiguration이 @EnableWebSocketMessageBroker로 STOMP 엔드포인트와 심플 브로커를 등록한다. 엔드포인트·프리픽스는 모두 websocket.stomp.server.* 설정에서 읽는다(config/websocket/WebSocketConfiguration.java:13-34).

    • 엔드포인트 /ws/stomp, 앱 destination /publish, 브로커 /subscribe, user /user(application.yaml.example:188-197).

    프로파일 / 포트¶

    프로파일 포트 비고
    default(로컬) 9041 application-default.yaml.example:5
    dev (yaml) 개발 서버
    prod (yaml) 운영
    • 공통 application.yaml은 address: 0.0.0.0, 세션 타임아웃 120m, shutdown: graceful(application.yaml.example:6-13).
    • spring.main.allow-circular-references: true — 레거시 호환(보안설정↔AdminService 상호참조) 위해 유지(application.yaml.example:25-26).
    • PageHelper pageSizeZero: true — pageSize=0일 때 전체조회하던 레거시 동작 복원, 삭제 금지(application.yaml.example:200-206).

    시크릿 정책

    application*.yaml은 gitignore 대상이며 *.yaml.example(placeholder)만 커밋된다. 클론 시 .example→실파일 복사 후 실값을 채워야 기동한다. 메일 발송 계정(MailFlowConfiguration)도 mail.flow.username/mail.flow.password로 외부화돼 있다(MailFlowConfiguration.java:22-26).
