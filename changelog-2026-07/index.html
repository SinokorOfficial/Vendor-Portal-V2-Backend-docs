    2026-07 변경 이력¶

    role_id 재설계 — 관리자 판정 role 기반 + self-describing role_id (PR #69)¶

    role_id 체계를 self-describing(<MODULE 3자리><seq 2자리>, 관리자=ADMIN)로 재설계하고 그에 맞춰 백엔드를 정렬했다. ① 관리자 판정을 로그인계정(user_id='admin')이 아니라 권한(ROLE_ID='ADMIN')으로 전환 — ExtendBaseService.isAdminRole()(세션 LoginUser.roleId 에 ADMIN) 신설로 VmsCommonService·EirService·MdmNoticeService 의 "admin".equals(userId) 대체, 매퍼 admin 판정 4곳 → ROLE_ID='ADMIN', CmsLoginLog/CmsVisitLog 로그 제외를 USER_ID!='admin' → NOT EXISTS(role ADMIN). ② self-describing 대응 — MdmNotice 공지 모듈필터 DECODE(SUBSTR 1,4) → SUBSTR(ROLE_ID,1,3)(접두어 3자리=MODULE_DIV), CmsUserMgt selectList 전체조회 예외 ROLE_ID='ADMIN' OR LIKE '%00'(모듈 관리 tier), CmsCommonPopup selectRole 의 옛 NOT LIKE '1%'(새 스킴선 '1' 시작 role 없어 무력화 → 비관리자에게 ADMIN·%00 노출) 버그 수정. ③ 버그 수정 — ORA-01427(selectTree·selectCorp SYSTEM_DIV=(스칼라 서브쿼리) → IN, 다중 SYSTEM_DIV 유저), 역할별 메뉴 권한관리 복사의 BTN_TP/BTN_IMAGE 누락(버튼이 BTN_TP=NULL 로 들어가 화면 미노출), 역할 삭제 가드(countUserRole — 배정 유저 있으면 삭제 차단, 고아 방지). ④ 레거시 겸용(dual-role) — 유저가 구+신 role 을 동시 보유하면 레거시(구 role 읽음)·V2(신 role 읽음) 무수정 겸용이 되나, Admin.selectMenuButtonList 가 (MENU_ID,ROLE_ID) 조인이라 버튼이 2중 노출 → DISTINCT 추가로 방지(메뉴는 기존 DISTINCT 라 무관).

    CmsUserMgt 조회 범위 role 기반 확장 (PR #68)¶

    selectList 가 리터럴 'admin' id 만 corp 스코프 필터 예외라, admin 과 같은 권한(role)이어도 다른 id 유저는 소속 corp(SYSTEM_DIV) 매칭이 없으면 빈결과였다. ROLE_ID LIKE '1000-%'(내부/관리자 role)이면 corp 스코프를 우회(전체 조회)하도록 확장 — 대시보드 관리자 판정('1000-01')과 동일 결.

    레거시→V2 SSO 자동로그인 핸드오프 (PR #62·#63·#64)¶

    레거시(partner) 지정 사용자를 V2(partner-v2)로 무비번 자동로그인시키는 카나리아 핸드오프. ① JwtAuthenticationFilter 가 SSO 인증 성공 시 SecurityContext 를 세션(HttpSessionSecurityContextRepository)에 명시 저장 — SB6 SecurityContextHolderFilter 는 요청 종료 시 자동 저장을 안 해, 이 저장이 없으면 SSO 링크(?token=) 진입이 세션으로 이어지지 않아 V2 로그인 화면으로 떨어졌다(#62). ② JwtSwitchingLoginUserAuthenticationProvider 는 기존 세션이 토큰과 동일 사용자일 때만 재사용하고 다르면 토큰 사용자로 스위칭 — 한 브라우저에서 A 세션에 B 토큰이 와도 A로 남던 세션 꼬임 해소(#63). ③ selectRoleId 에 DISTINCT + TB_CMS_USER_CORP_MGT 조인으로 roleId 카테시안 중복 제거(#64). 상세: 보안·인증 §SSO 전환.

    개발자 문서 Partner Portal 브랜딩 (PR #65·#66)¶

    좌상단 로고/파비콘을 V2 파비콘으로, 헤더·상단 탭을 톤다운 블루(#2C6CB0)+흰 글자로, 우상단은 레포명 숨기고 github 아이콘만(라이트/다크 토글을 github 왼쪽으로·여백 통일), 좁은 화면에서도 github 를 헤더에 유지+드로어 제목 개행 2줄. 표기 Vendor Portal V2 → Partner Portal(repo 주소·vps=Vendor Portal Service 코드 약어·기술적 V2 는 보존).

    CI/CD GitHub-hosted(ubuntu-latest) 복귀 (PR #60)¶

    GitHub Actions 분(minute) 복구로 ci·deploy·docs-deploy 3개 워크플로를 self-hosted Windows 러너 → GitHub-hosted 로 되돌림. 활성=hosted 원본(ci=gradle build+Trivy CVE+SBOM, deploy/docs=기존 hosted 잡), self-hosted(PowerShell/stub) 버전은 각 워크플로 하단 주석 블록으로 보관(각 줄 # 제거로 언제든 재전환). ⚠️ 전제 = GH 분 실제 복구(아직 소진이면 hosted 잡이 러너 할당 실패로 즉시 실패). 마이그레이션 함정 §3.11.

    로그인 로그 V2 유입 마커 LOGIN_MSG='Login at V2' (PR #59)¶

    레거시 partner 와 같은 Oracle DB(TB_CMS_LOGIN_LOG)를 공유하므로, V2 백엔드가 남기는 모든 로그인로그 레코드에 LOGIN_MSG='Login at V2' 를 표기해 두 시스템을 구분(기존엔 insertLoginLog INSERT 에 LOGIN_MSG 컬럼 자체가 없어 NULL 이 들어갔다). 접속 IP(CLIENT_IP)는 forward-headers-strategy: native 덕에 실제 사용자 공인 IP 로 정확히 기록됨 — 마이그레이션 함정 §4.4.

    배포 OIDC 토큰 캐시 무효화 → containerapp update 직전 재로그인 (PR #58, 프론트 #79)¶

    azure/login OIDC 는 리프레시 토큰이 없어, 긴 az acr build(백엔드 gradle=수 분) 후 캐시 토큰이 만료되면 다음 az containerapp update 가 Could not retrieve credential from local cache 로 실패한다. Build image in ACR 와 Update Container App 사이에 azure/login@v2 재로그인 1스텝 추가. 마이그레이션 함정 §3.12.

    CI/CD self-hosted Windows 러너 이전(→ 2026-07-23 hosted 복귀, 위 참고)¶

    GitHub Actions 월 쿼터 소진으로 deploy.yml 을 온프렘 self-hosted Windows 러너(runs-on: [self-hosted, Windows, vendor-portal-v2], shell: powershell)로 이식. 이미지 빌드는 az acr build(클라우드)라 러너엔 Git + PowerShell + Azure CLI 만 필요(Docker/JDK 불필요). bash→PowerShell 이식($LASTEXITCODE 명시 판정, application-azure.yaml 복원은 UTF-8 BOM 없음으로 바이트 동일). OIDC(azure/login)는 self-hosted 에서도 정상. 백엔드 이미지 빌드는 인코딩 이슈 없이 통과(프론트는 az acr build 가 vite ✓ 출력 시 cp949 크래시 → 러너 시스템 로케일 UTF-8 로 해결, 마이그레이션 함정 §3.11). ⚠️ ci.yml·docs-deploy.yml 은 아직 self-hosted 스텁(checkout만) — 이식엔 러너 JDK 21·Python + peaceiris(Docker 액션) 대체 필요.

    미사용 화면 3종 + 관련 死코드 정리 (PR #49, 프론트 #69)¶

    미사용 확정 화면 CmsMyBooking(부킹 스케줄러)·MdmPricingMgt(단가관리)·CmsGridLayoutCopyMgt(레이아웃 복사) 관련 백엔드 제거. 앞 둘은 controller/service/dao/mapper 전체 삭제(+PricingExcelColumn·고아 MdmExcelUploadService). gridLayout/copyLayout·gridLayout/selectUserList(호출 0 死 엔드포인트) 제거 — 공용 gridLayout/select·save·copy·delete·saveDefaultGridLayout·selectCarrier·downloadTemplate4TES는 보존. 고아 downloadTemplate(단수) 엔드포인트/서비스 메서드도 제거(단가관리 전용이었음). ★CmsGridLayoutCopyMgt 화면 자체는 존재하지 않는 /api/cms/select|save를 부르던 死화면이라 프론트 폴더만 삭제.

    미사용 스토리지 추상화 정리 — StorageService init()-only (PR #49)¶

    파일 저장/다운로드가 NAS/FTP로 일원화돼 S3 upload/download/load 구현은 운영 미사용(호출 0). StorageService 인터페이스를 init()(부팅 시 업로드 디렉터리 생성)만 남기고, AwsS3FileService·FileSystemStorageService의 미사용 메서드 + StorageFileNotFoundException 제거. ⚠️ S3 관련 설정(cloud.aws/AwsS3Property)·의존성은 존치하나 현재 코드 참조 0(향후 정리 후보).

    미사용 세션 필드 + 死 선사(Carrier) 기능 제거 (PR #45, 프론트 #65)¶

    LoginUser 세션값 전수조사(백/프론트) 후 미사용 20필드 + compId(세팅조차 안 됨) 제거, 유지 필드엔 [BE·FE]/[BE]/[FE] 사용현황 주석. AdminService setter·ExtendBaseController.getCompId()·selectUser 死컬럼 18개 정리(serialVersionUID 고정이라 기존 Redis 세션 무영향). 아울러 연결 DB에 TB_MDM_CARRIER/TB_CMS_CARRIER_SITE 자체가 없어(ORA-00942 실측) 死상태인 선사 기능 제거 — MdmCarrierMgt(선사관리)·CmsCarrierSiteMgt(선사 사이트 관리) 화면 통삭제 + imageServerLocation(선사 로고 S3 base) 제거. CmsCommonPopup.selectCarrier는 MdmPricingMgt/MdmExcelUpload가 공유해 존치, CmsMyBooking 선사 조인 디커플은 후속.

    메뉴 검색 오류/개선 (PR #46·#47)¶

    CmsMenuMgt selectMenuList의 MENU_ABBR 필터에 LIKE 누락(약어 검색 시 ORA-00920) 수정 + 검색 바인드를 UPPER(#{...})로 감싸 대소문자 무관 검색. (API는 {SEARCH:{...}} 래핑 필요, top-level은 NPE.)

    컨테이너 타임존 Asia/Seoul (PR #46)¶

    에러로그 등이 Oracle CURRENT_TIMESTAMP(=JDBC 세션TZ=JVM 기본TZ)로 기록되는데 Azure 컨테이너 기본이 UTC → KST−9h(04시=13시)로 찍힘. 리전(Korea Central)은 위치일 뿐 TZ가 아님. Dockerfile ENV TZ=Asia/Seoul(temurin tzdata 내장)로 CURRENT_TIMESTAMP·앱 시간을 KST 정렬.

    미사용 파일 백엔드 정리 + 네이밍 정렬 (PR #42·#43·후속)¶

    프론트/외부 호출이 전무한 Cost 첨부기능(VmsCostController·VmsCostService)과 그 전용 진입점(KeyService), 이들만 쓰던 PKG_CM_FILE(SP_GET_FILE_UPLOAD/SP_SET_FILE) 호출 체인, 死메서드 12개(fileUploadGpt·logoImageDownload·base64ImageDownload* 등)와 死엔드포인트(/fileUploadGpt·/fileDownload·/logoImageDownload)를 제거(약 1,320줄↓). 이어 FileDataController/FileDataService 의 메서드명과 엔드포인트 URL 을 verb-first 로 정렬했다 — /api/file/fileUpload→/uploadFile, /fileUploadInv→/uploadInvFile, /fileDelete→/deleteFile, /templateDownload→/downloadTemplate, /templateDownload4TES→/downloadTemplate4TES(메서드명 동일 규칙, uploadFileNasPath→uploadFileNas 포함; TES 템플릿 생성 private 헬퍼 tally/lhdc/lash/lashCon/tug→get*Template). 아울러 死스텁 엔드포인트 POST /api/vendor/comm/invoiceFileUploadIF(빈 응답·호출 0)도 제거. ⚠️ 엔드포인트 개명은 API 경로 변경(breaking) 이라 프론트 호출부(FileService·첨부 그리드·TES 템플릿 다운로드 등)를 같은 릴리스에서 함께 수정해 반영했다 — 백엔드·프론트를 동시 배포해야 한다. 존치 다운로드(/api/file/downloadFileNas)와 파트너 ZIP 다운로드 경로는 그대로다. 아울러 다건 조회 selectFileLists(MNGT_NO IN)를 selectFileList 에 동적 WHERE(<choose>: 단건 = / 리스트 IN / 그 외 1=0)로 흡수하고 유일 호출처(CmsInvoiceFileUploadPopup) 1곳을 이관 — 엔드포인트/매퍼 1쌍 감소(관리포인트 축소).

    공통 프로시저 호출 통합 (executeVmsCommonProcedure)¶

    select/save 두 경로를 합친 상위집합 메서드와 전용 엔드포인트 POST /api/vendor/comm/executeVendorCommonProcedure 신설. @Transactional·IN 커서 항상 처리·OUT 커서 1~20·커서별 개별 resultMap(ORA-17006 방지). 기존 select/save 는 존치. 프런트는 EIR 제외 전 모듈 전환. 상세: ADR-0004, vps §2-2.

    배포 컷오버 graceful shutdown 실동작 (PR #31)¶

    Dockerfile ENTRYPOINT 에 exec 추가. sh -c "java …" 는 dash 가 java 를 자식으로 fork → PID 1(셸)이 SIGTERM 을 JVM 에 전달 못해 graceful shutdown 이 무력화됐다. exec java … 로 JVM 이 PID 1 이 되어 SIGTERM 직접 수신. 상세: 마이그레이션 함정 §3.10.

    CI 품질게이트 워크플로 추가 (PR #27)¶

    dev/main PR 에서 빌드(./gradlew build)·Trivy 의존성 CVE(리포트)·SBOM 을 실행한다. 리포트 전용·비차단. 사용법은 시작하기 §CI 품질게이트, 도입 함정은 마이그레이션 함정 §3.9.
