    Vendor Portal Service (vps) 도메인 코드 워크스루¶

    com.sinokor.vp.vps 는 Vendor 시스템 전반의 공통 기능을 담는 도메인이다. 핵심은 Oracle 패키지 프로시저를 화면이 보낸 메타데이터로 동적 실행하는 공통 조회/저장 로직이며, 그 위에 엑셀 업로드 파싱, Microsoft Graph 메일 전송, 보험증권 GPT 추출이 얹혀 있다.

    1. 도메인이 하는 일¶

    영역 책임 주요 클래스
    공통 프로시저 실행 패키지/프로시저명 + 파라미터를 받아 In/Out 인자를 동적 구성, 다중 REF CURSOR 결과셋 처리 VmsCommonService, VmsCommonDao
    메일 전송 Microsoft Graph SDK v6로 메일 발송 + 전송 로그 적재 VmsSendMailController, VmsSendMicrosoftGraphMailService
    엑셀 업로드 검수료/강취료/결해속비/예선료/컨테이너 무브먼트/수리견적 엑셀 파싱 VmsCommonExcelController, VmsExcelCommonService, VmsExcelFacade
    보험 클레임/증권 조회, 보험증권 PDF를 외부 GPT API로 추출 VmsInsuranceController, VmsInsuranceService

    데이터 캐리어는 전부 DMap, 응답은 ResponseVo.of(map).build() 규약을 따른다.

    패키지 vps / 매퍼 vms

    Java 패키지는 vps(vps/comm/...)지만 MyBatis 매퍼 네임스페이스/파일 경로는 vms다 — resources/mapper/oracle/vms/VmsCommon-mapper.xml. 클래스 prefix도 Vms*다.

    2. 대표 유스케이스¶

    2-1. 공통 프로시저 조회 (/selectVendorCommonProcedure)¶

    화면은 호출할 패키지/프로시저명과 파라미터만 DATASET 배열로 보낸다. 서버가 ALL_ARGUMENTS(프로시저 PKG_CM.SP_GET_ARGUMENT)에서 인자 메타를 읽어 In 파라미터를 바인딩하고, OUT REF CURSOR 개수에 맞는 매퍼를 골라 호출한다.

    sequenceDiagram
    participant FE as Frontend
    participant C as VmsCommonController
    participant S as VmsCommonService
    participant D as VmsCommonDao
    participant DB as Oracle (PKG_*)

    FE->>C: POST /selectVendorCommonProcedure (DATASET)
    C->>C: COMP_CD 검증, USER_ID/CORP_CD 세팅
    C->>S: selectVmsCommonProcedure(userId, param)
    loop DATASET 각 항목
        S->>D: selectVmsCommonProcedureParam (인자 메타 조회)
        D->>DB: CALL PKG_CM.SP_GET_ARGUMENT
        S->>S: IN / OUT(REF CURSOR) / OUT(VARCHAR2) 필터링
        S->>D: selectVmsCommonProcedureOut{N} (커서 개수 N)
        D->>DB: CALL PACKAGE.PROCEDURE(IN..., OUT cursor...)
        DB-->>S: resultCd + result1..resultN
        S->>S: resultCd=N/E 면 errorMessage, CLOB/BLOB 변환
    end
    S-->>C: { 프로시저명: { 커서명: rows } }
    C-->>FE: ResponseVo

    핵심 코드 위치:

    • 컨트롤러 진입·세션 보정: src/main/java/com/sinokor/vp/vps/comm/controller/VmsCommonController.java:26
    • 인자 메타 조회 후 IN/OUT 필터: src/main/java/com/sinokor/vp/vps/comm/service/VmsCommonService.java:66
    • 커서 개수별 DAO 분기(1~20): src/main/java/com/sinokor/vp/vps/comm/service/VmsCommonService.java:108
    • 프로시저 내부 오류코드(N/E) 처리: src/main/java/com/sinokor/vp/vps/comm/service/VmsCommonService.java:177
    • 동적 CALL + REF CURSOR 매핑(SP_GET_ARGUMENT): src/main/resources/mapper/oracle/vms/VmsCommon-mapper.xml:7, :173

    IN 파라미터 명명 규칙

    OUT 커서 개수에 따라 selectVmsCommonProcedureOut1~Out20 매퍼가 별도로 존재한다. IN 파라미터는 프로시저 인자명에서 선두 P_ 를 제거해 DMap 키와 매칭하며(P_USER_ID→USER_ID), UPST_USER_ID 는 세션 사용자로 강제 치환된다. 타입별(NUMBER/DATE/CLOB/BLOB) 변환은 setInParam(VmsCommonService.java:754)에서 처리한다.

    2-2. 공통 프로시저 통합 실행 (/executeVendorCommonProcedure) — 현행 표준¶

    selectVmsCommonProcedure(조회)와 saveVmsCommonProcedure(저장)를 합친 상위집합 메서드다. 화면이 조회/저장을 구분하지 않고 한 엔드포인트로 호출한다. 배경·결정은 ADR-0004.

    • 단일 통합 매퍼(익명 PL/SQL 블록): IN 커서가 있을 때만 DECLARE, OUT VARCHAR 1개면 resultCd·여러 개면 ARR_OUT_PARAM, OUT 커서는 OUT_CURSOR_COUNT 로 1~20 동적 결정(VmsCommon-mapper.xml의 executeVmsCommonProcedure).
    • @Transactional — 조회는 무해(빈 커밋), 저장은 원자성 보장. IN 커서는 있으면 저장 방식으로 동적 구성, 없으면 생략.
    • OUT 커서 슬롯마다 개별 resultMap(retExec1~retExec20) — 하나를 공유하면 MyBatis auto-mapping 캐시가 서로 다른 컬럼셋 커서에 오적용돼 ORA-17006이 난다.
    • resultCd(N/E) 검사는 호출 후, 사유 메시지는 P_RS_ERR 커서에서 우선 읽고, 없거나 비어 있으면 첫 커서(result1=P_RS)로 폴백한다(VmsCommonService.java:661 — P_RS 에 사유를 담는 프로시저가 있어서). OUT 커서 0개는 no-op(:641).

    핵심 코드 위치:

    • 통합 서비스 메서드: src/main/java/com/sinokor/vp/vps/comm/service/VmsCommonService.java:502
    • 전용 엔드포인트: src/main/java/com/sinokor/vp/vps/comm/controller/VmsCommonController.java:60
    • 통합 매퍼·개별 resultMap: src/main/resources/mapper/oracle/vms/VmsCommon-mapper.xml:90

    프런트 전환 범위

    전 모듈(EIR 포함 — 2026-08-12 전환 완료)의 프런트 select/saveVendorCommonProcedure 호출이 executeVendorCommonProcedure 로 전환됐다(프런트 실호출 0건). 기존 select/save 메서드·매퍼·HTTP 엔드포인트는 존치 — EirService 가 서버 내부(Java)에서 selectVmsCommonProcedure/saveVmsCommonProcedure 를 계속 호출하기 때문이다(EirService.java:628 등 4곳). sendMail·uploadExcel 등 다른 엔드포인트는 전환 대상이 아니다.

    2-3. 날짜 인자·커서 컬럼 자동 절단 (setDateColumn) — ★함정¶

    IN 파라미터와 IN 커서 컬럼은 이름 접미사만 보고 값이 잘린다. 타입 선언이 아니라 명명 규약이 동작을 결정한다.

    접미사 요구 자릿수 예
    _DT 8 (yyyyMMdd) FM_DT, GRP_INV_DT, JOB_DT, INV_DT
    _DI 12 (yyyyMMddHHmm) INST_DI, UPST_DI
    _DM 6 (yyyyMM) —
    _DY 4 (yyyy) — 
    retValue = value.replaceAll( "[-T:]", "" ).substring( 0, val );   // 길이검사 없음

    적용 지점은 두 곳이다 — IN 파라미터는 setInParam 이 ARGUMENT_NAME 에서 선두 P_ 를 뗀 이름으로, IN 커서는 각 행의 IC_COLUMN_NAME 으로 판정한다(VmsCommonService.java:367·:620·:793). 커서 컬럼 목록은 PKG_CM.SP_GET_ARGUMENT 가 cm_cd(CMPIC) 매핑의 실제 테이블 컬럼에서 뽑는다.

    길이 미달이면 500, 구분자가 다르면 조용히 썩는다

    • 자릿수 미달 → StringIndexOutOfBoundsException: begin 0, end 8, length 4. 운영 에러로그 실측 18건(2025-07-16~2026-01-21, 유저 8명), 잘린 길이 1/2/4/6/7자.
    • /·. 구분자 → replaceAll 이 지우는 것은 -, T, : 뿐이라 2026/08/31 은 2026/08/ 로 잘려 예외 없이 저장된다.

    2026-08-31 기준 백엔드는 미수정이다. 프론트가 전송 직전 관문(axios 인터셉터)에서 자릿수 미달을 차단하고 / 구분자를 정규화하도록 막아 뒀다(FE PR #158). 따라서 프론트를 거치지 않는 호출은 여전히 500 이 난다 — 다른 클라이언트를 붙이거나 이 서비스를 재사용할 때 반드시 고려할 것.

    VSL_DT 만 예외 — 규칙을 넓히면 데이터가 사라진다

    if ( columnNm.equals( "VSL_DT" ) ) return retValue;   // 정확 일치
    TES(LASH/LHDC/TALLY/TUG) 커서가 VSL_DT 에 yyyyMMddHHmm 12자를 의도적으로 싣는다. 이 예외를 지우거나 endsWith("_DT") 로 일반화하면 예외 없이 시각만 잘려나간다. 새 날짜 컬럼을 만들 때도 8자가 아니면 _DT 로 끝나는 이름을 붙이지 말 것.

    • 값이 null 이거나 빈 문자열이면 절단을 건너뛴다. 조회 기간을 비워 보내는 화면들이 이 동작에 의존한다(FM_DT/TO_DT 미입력 = 전기간).
    • 핵심 코드: src/main/java/com/sinokor/vp/vps/comm/service/VmsCommonService.java:824

    2-4. 메일 전송 (/sendMail)¶

    POST /api/vendor/comm/sendMail 은 MAIN 파트(DMap)를 받아 Microsoft Graph로 발송한다. 메일 서버(앱 등록) 자격정보 자체도 공통 프로시저로 DB에서 조회한다.

    1. 컨트롤러가 세션 userId 와 빈 FROM 보정 → VmsSendMicrosoftGraphMailService.sendMail 호출. VmsSendMailController.java:40
    2. PKG_CM.SP_GET_AAD 로 Azure 앱 자격정보(CLIENT_ID/TENANT_ID/CLIENT_SECRET/SCOPE) 조회. VmsSendMicrosoftGraphMailService.java:67
    3. ClientSecretCredential + GraphServiceClient(SDK v6) 구성, Message(HTML 본문 + TO/CC/BCC) 작성. VmsSendMicrosoftGraphMailService.java:82
    4. graphClient.users().byUserId(emailFrom).sendMail().post(...) 로 전송. VmsSendMicrosoftGraphMailService.java:267
    5. PKG_CM_EMAIL.SP_SET_EMAIL 로 전송 로그 적재(saveVmsCommonProcedure). VmsSendMicrosoftGraphMailService.java:298

    첨부파일 비활성

    현재 첨부파일 처리(FTP/NAS·MultipartFile)는 전부 주석 처리되어 본문 전용이다(VmsSendMicrosoftGraphMailService.java:145 이하). 첨부 지원이 필요하면 SDK v6 첨부 API로 재구현해야 한다 — 레거시 fileAttachment.contentBytes 방식은 동작하지 않는다.

    경로 prefix가 셋

    /api/vendor/comm(VmsCommonController·VmsSendMailController), /api/vms/comm(VmsCommonExcelController), /api/insurance(VmsInsuranceController) 로 나뉜다. 엑셀 업로드는 /api/vms/comm/uploadExcel 하나뿐이다 — 동명의 /api/vendor/comm/uploadExcel 빈 스텁이 있었으나 死코드로 제거(2026-09-07).

    4. 엑셀 업로드 TYPE 분기¶

    VmsExcelCommonService.uploadExcel 은 TYPE 값으로 파서를 고른다(VmsExcelCommonService.java:22).

    TYPE 의미 시작행 파서
    INSP_EXPN 검수료 1 헤더 기반 excelHeaderByData
    LINE_HANDLE_EXPN 강취료 1 헤더 기반
    LASHING_EXPN 결해속비 1 헤더 기반
    TUG_EXPN 예선료 1 헤더 기반
    CNTR_MOVE Container Movement(Movement) 1 고정 컬럼 매핑(EQ_NO 등)
    ESTIMATE Repair Estimate 2 헤더 기반
    FD_CNTR_MOVE Container Movement(Feeder) 1 고정 컬럼 매핑

    헤더 기반 파서는 첫 행을 헤더로 삼아 행을 DMap 으로 변환하며, 수식 셀은 FormulaEvaluator 로 평가한다(VmsExcelFacade.java:99). 검증(uploadExcelChk)은 VmsExcelChkFacade 가 담당한다.

    5. 외부 연동 · 주의점¶

    • Microsoft Graph (SDK v6 / Kiota): 레거시의 TokenCredentialAuthProvider·UserSendMailParameterSet 가 제거되어, GraphServiceClient(credential, scopes) + SendMailPostRequestBody 로 마이그레이션됨(VmsSendMicrosoftGraphMailService.java:23,:89,:265). 자격정보는 코드 하드코딩이 아니라 PKG_CM.SP_GET_AAD 로 DB 조회한다.
    • 보험증권 GPT 추출: WebClient(Reactor Netty)로 외부 https://AZURE-GPT-HOST/extract_insurance_gpt 에 멀티파트 POST. BASE_URL이 소스에 하드코딩되어 있고, 타임아웃이 사실상 무제한(999999999)으로 설정돼 있다(VmsInsuranceService.java:33,:157). 추출 결과의 통화/금액은 setDataSplitAmount 가 분리·코드 매핑한다(VmsInsuranceService.java:93).
    • 다중 결과셋 한계: 통합 경로(executeVmsCommonProcedure)는 OUT 커서 1~20을 조회·저장 공통으로 지원한다(단일 매퍼 <if OUT_CURSOR_COUNT>). 존치된 레거시는 조회 Out1~Out20, 저장 Out1~Out5까지만 매퍼가 정의돼 있다(VmsCommonDao.java:14,:60). 20 초과 시 통합 경로는 예외를 던지고(VmsCommonService.java:644), 레거시는 분기 없이 무시된다.
    • SQL 오류 로깅: 과거에는 프로시저 호출 예외 시 서비스가 파라미터 덤프를 직접 insertErrorLog("03") 로 적재했으나, 전역 에러 적재가 REQUEST/PAYLOAD 를 붙이면서 같은 에러가 2행 쌓이는 중복이라 제거됐다(PR #97). 지금은 예외를 그대로 전파하며, 파라미터는 전역 적재의 PAYLOAD 로 남는다.
    • 인증: 위 엔드포인트는 application.yaml security.request-permit-all-mappings 에 없으므로 전부 로그인(세션) 필요다.

    6. DB 프로시저(pkg_fds) 주의점 — 선사 스왑·컨테이너 무브¶

    피더 화면(FdsOrdMgt·FdsCntrMoveUpload 등)의 저장은 공통 프로시저 경로로 VENDOR.pkg_fds 의 SP(sp_set_ordermgt→sp_set_order→sp_set_eqno→sp_set_fdeqmv, Movement Upload 는 sp_set_eqmv_new)를 호출한다. 2026-08-20 스왑 풀사이클(재스왑→저장→스왑백→저장) 실측 검증에서 확정된 설계·함정을 기록한다(결함 8건 수정·운영 반영 완료 — 변경 이력 참고).

    선사 스왑(sp_swap4company) 설계

    • 스왑은 포탈 데이터(tb_fds_*)를 옮기지 않는다. tb_fds_swapcomp(from/to/org_ord_no/iscurrent/seq) 계보 기록 + 선사 EDI 만 이관(SNKO↔HALK: liner.t_oceq013 ↔ hliner.t_oceq011).
    • 스왑 후에도 사용자는 원선사 comp_cd 로 계속 입력한다(상대 선사에 오더가 생기지 않음). 저장 merge 가 t.ord_no = s.from_ord_no and s.iscurrent='Y' 조인으로 스왑을 인지해 상대 선사 EDI 에 blno = s.to_ord_no 로 적재하고, 스왑백 뒤에는 다시 원선사 EDI 로 돌아간다.

    테이블 구조 팩트(실측)

    • LINER.T_OCEQ013 = 테이블 / HLINER.T_OCEQ013 = 뷰(t_oceq011 ⋈ t_occd106 GATE 그룹, bkno→blno 별칭 — 키보존 조인뷰라 DELETE 가능). T_OCEQ011_E 는 존재하지 않음(실체는 양쪽 T_OCEQ013_E). _e = SOC(soc='Y') 오더 적재처.
    • TMP_FDS_EQMV·TMP_FDS_ORD·TMP_MVS_CNTR_MV 는 이름과 달리 영구 테이블(temporary=N, TMP_ERR 만 세션 템프). SP 초입 delete 가 자기(emp_nm) 행만 지우므로 유저별 마지막 저장분이 잔존한다 — tmp 를 읽는 쿼리(특히 결과 표시 커서)는 반드시 emp_nm = p_user_id 필터를 동반해야 타 유저 잔존행이 섞이지 않는다.
    • HLINER T_OCEQ011 BEFORE 트리거가 무브 종류별로 bkno 를 재배정한다(소스 열람 권한 없음·실측): IFI/IE 등 일부 수입계 무브는 입력 bkno 를 무시하고 컨테이너+시점으로 부킹을 자체 매칭(실패 시 NULL), IFE/IFT/OEE 등 대부분은 입력값 존중. tpsz 도 재계산(포탈 D4→ISO 22GP). LINER 측엔 이런 재배정이 없다. → 테스트 시 IFI+가상 날짜 조합은 bkno NULL 아티팩트를 만든다.
    • t_brgcntr(바지 컨테이너)는 F% 무브에만 관여하며 brgvslcd 등 키값은 tmp 가 아니라 tb_fds_eqno 실값으로 매칭한다. Movement Upload 는 피더무브(F%)를 입력받지 않는다(주석 명시).

    그룹인보이스 저장 차단 규칙(sp_get_errcheck FD, 2026-08-20 확정)

    • grp_inv_no 가 있는 오더의 저장은 E/O = 차단, 수입(I) = D/O 발행일시가 입력값(tmp)·DB 기발행값 어느 쪽에든 있으면 허용(신규 D/O 발행 입력, 기발행 오더의 수정 모두 통과) — 6케이스 실오더 매트릭스로 검증.
    • 주의: sp_set_order 의 merge 는 입력값 x.doissue_dtm 으로 DB 를 덮어쓴다 — 화면이 D/O 값을 싣지 않고 저장하면 발행정보가 지워질 수 있는 기존 구조(화면은 전체 행을 보내는 계약).

    검증 기법

    스왑·저장 SP 에는 내부 commit 이 없어(실측) JDBC autoCommit=false + 마지막 ROLLBACK 으로 운영 복제 DB(.100)에서 무흔적 반복 테스트가 가능하다. IN 커서는 anonymous block open ic for select ... from dual(tmp_fds_eqmv 18컬럼 순서)로 재현하고, 파싱 에러(ORA-00979 등)는 explain-plan 일괄 파싱으로 실행 전에 잡을 수 있다.
