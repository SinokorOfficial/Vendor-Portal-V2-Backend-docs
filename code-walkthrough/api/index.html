    API 파트너(Partner API) 도메인 워크스루¶

    외부 파트너사가 호출하는 공개 API 묶음이다. EIR(컨테이너 기기수도증) 취소 전송, 수리비 면제 첨부파일 ZIP 다운로드, EIR 취소대상 조회 등을 제공하며, 중국 SIPG(상하이항) ESB와 연동한다.

    1. 이 도메인이 하는 일¶

    • 패키지: com.sinokor.vp.api.partner — 컨트롤러/서비스/DAO 3계층.
    • 진입점 컨트롤러는 PartnerController이며 @RequestMapping("/api/partner")로 매핑된다 (src/main/java/com/sinokor/vp/api/partner/controller/PartnerController.java:28).
    • 핵심 책임은 두 가지다.
      1. EIR 취소 — 포털이 호출하는 실제 API. 취소대상 EIR을 조회해 건별로 SIPG ESB에 취소 전송하고 응답을 로그에 적재한다.
      2. 수리비 면제 파일 다운로드 — eBiz(전자상거래) 쪽에서 호출. NAS의 첨부파일들을 모아 ZIP으로 스트리밍한다.
    • 모든 호출은 PartnerService.insertCallApiLog(...)로 TB_CMS_API_LOG 테이블에 기록된다 (...api/partner/service/PartnerService.java:37, 매퍼 ...mapper/oracle/api/partner/Partner-mapper.xml:12). 호출자 IP 도 CALL_IP 컬럼에 함께 적재되며(X-Forwarded-For 체인, PR #78) 조회 SP 측 출력 컬럼 추가(DB 작업)까지 완료돼 CmsApiLog 화면에서 확인할 수 있다.

    보안 설정

    /api/partner/**는 GET·POST 모두 인증 없이 허용된다 (src/main/resources/application.yaml:95, :107의 security.request-permit-all-mappings). 외부 파트너 호출을 받기 위한 공개 엔드포인트다.

    2. 핵심 엔드포인트¶

    메서드 경로 설명 정의 위치
    GET /api/partner/getCancelEir 취소 대상 EIR 정보 조회(@RequestBody DMap) PartnerController.java:57
    POST /api/partner/cancelEir 포털 실호출 — EIR 취소 SIPG 전송 PartnerController.java:77
    GET /api/partner/download 단일 컨테이너 수리비 면제 파일 ZIP 다운로드 PartnerController.java:123
    GET /api/partner/downloadAll 다중 컨테이너 일괄 ZIP 다운로드 PartnerController.java:167

    DAO와 실제 호출 경로 불일치

    PartnerDao에는 getCancelEir 메서드가 선언돼 있으나, Partner-mapper.xml에 실제 정의된 SQL은 decodeBlNo와 insertCallApiLog 둘뿐이다. 컨트롤러가 쓰는 getCancelEir는 DAO가 아니라 PartnerService.getCancelEir(저장프로시저 PKG_API.SP_GET_CANCEL_EIR 호출) 경로다. DAO의 이 선언은 사용처가 없는 잔재로 보인다. (같은 잔재였던 getToken 선언과 /api/partner/getToken 엔드포인트는 2026-08-21 정리에서 삭제 — 운영 API 로그상 마지막 호출 2025-12-30.)

    3. 유스케이스 A — EIR 취소 (POST /cancelEir)¶

    가장 핵심 플로우다. 취소대상을 프로시저로 조회한 뒤, 건별로 토큰을 사용해 SIPG에 취소 요청을 보낸다 (PartnerController.java:77~121).

    sequenceDiagram
    participant P as 포털
    participant C as PartnerController
    participant PS as PartnerService
    participant ES as EirService
    participant V as VmsCommonService (Oracle 프로시저)
    participant SIPG as SIPG ESB<br/>(ESB-HOST)

    P->>C: POST /cancelEir {COMP_CD, BK_NO}
    C->>PS: getCancelEir(param)
    PS->>V: PKG_API.SP_GET_CANCEL_EIR
    V-->>PS: 취소대상 EIR 목록(P_RS)
    alt 취소대상 있음
        C->>ES: getValidTokenNew(COMP_CD)
        ES-->>C: access token (Redis 캐시)
        C->>PS: insertCallApiLog("EIR002", ...)
        loop EIR 건별
            C->>ES: setJson("PORTAL", item)
            ES->>V: PKG_EEIR.SP_RTNJASON → JSON
            C->>ES: sendSIPGNew(token, ..., opStatus="2", json)
            ES->>SIPG: POST EIR3.0~B01~200001
            SIPG-->>ES: status/receiptNo
            C->>ES: setEirResponse("PORTAL", result)
            ES->>V: PKG_EEIR.SP_SET_EIRLOG (로그 적재)
        end
        C-->>P: ResponseVo {MSG:[건별 결과]}
    else 없음
        C-->>P: ResponseVo {MSG:"There is no EIR to cancel."}
    end

    단계 요약:

    1. 취소대상 조회 — PartnerService.getCancelEir가 VmsCommonService.selectVmsCommonProcedure로 PKG_API.SP_GET_CANCEL_EIR를 호출해 P_RS 커서를 반환. 없으면 null (PartnerService.java:47~77).
    2. 토큰 획득 — EirService.getValidTokenNew(compCd). Redis(token:{compCd})에 캐시하고 분산락(lock:token:{compCd})으로 중복 발급을 막는다 (...eir/service/EirService.java:298).
    3. 건별 전송 — 각 EIR에 대해
      • EirService.setJson("PORTAL", item) → PKG_EEIR.SP_RTNJASON으로 전송 JSON 생성 (EirService.java:581).
      • EirService.sendSIPGNew(token, compCd, "PORTAL", bkNo, cntrNo, imex, eirNo, "2", json) → SIPG ESB EIR3.0~B01~200001에 POST. opStatus="2"가 취소를 의미하며, cntrNo·imex는 취소대상 커서의 CNTRNO/BND에서 채운다 (PartnerController.java:106, EirService.java:647).
      • EirService.setEirResponse("PORTAL", sendResult) → PKG_EEIR.SP_SET_EIRLOG로 응답 로그 적재 (EirService.java:795).

    컨트롤러가 호출하는 EirService 버전

    cancelEir는 eirService.setJson(...) / eirService.sendSIPGNew(...) / eirService.setEirResponse(...)를 쓴다. PartnerService에도 setJson이 있으나(PartnerService.java:79) 이 플로우는 EirService 쪽을 사용한다. 구버전 sendSIPG·getToken은 2026-08-21 정리(403efbd)에서 삭제됐고, ConcurrentHashMap 기반 getValidToken만 "사용 X" 주석과 함께 남아 있다(비활성).

    실패 응답

    토큰 발급 실패(비정상 응답·access_token/expires_in 누락 포함)와 SIPG 통신 자체 실패는 ExternalServiceException으로 올라가 502 + MSG000430으로 응답한다(PR #109·#115·#116). 상세는 EIR 워크스루(eir.md) 참고. SIPG가 응답한 오류(4xx 본문)는 예외가 아니라 건별 결과 MSG에 담긴다.

    4. 유스케이스 B — 수리비 면제 파일 다운로드 (GET /download)¶

    암호화된 B/L 번호를 복호화하고, NAS의 첨부파일들을 ZIP으로 묶어 응답 스트림에 직접 쓴다 (PartnerController.java:123~165).

    1. B/L 복호화 — PartnerService.decodeBlNo(HBLNO) → 매퍼가 Oracle SYS.CRYPTO.XDECRYPT로 복호 (Partner-mapper.xml:5).
    2. 호출 로그 — insertCallApiLog("API001", "EBIZ", ...).
    3. 파일 목록 조회 — FileDataService.fileDownloadNasList(fileMap). COMP_CD(SNKO/HALK/HSLI)에 따라 폴백 조회 (...admin/service/FileDataService.java:351).
    4. ZIP 스트리밍 — ZipOutputStream에 FileDataService.downloadFileNas로 받은 FTP 스트림을 4KB 버퍼로 복사. 응답 헤더는 Content-Type: application/zip, 파일명 [B/L] {CNTR_NO}.zip.

    downloadAll은 동일 패턴이되 MNGT_NOS를 콤마/하이픈(MNGT_NO-CNTR_NO)으로 분해해 여러 컨테이너를 반복 처리한다 (PartnerController.java:167~214).

    5. 외부 연동 · 주의점¶

    • SIPG ESB 연동은 모두 EirService에 집중된다. 신규 엔드포인트는 https://ESB-HOST/api/이며, 토큰 발급/검증(OAuth2~S01~100000/100001), 취소 전송(EIR3.0~B01~200001), 정보 조회(EIR3.0~B01~500002)를 사용. 요청에는 X-Signature(SHA-256 + 회사별 SALT, EirService.generateSignature :555), X-App-Id, X-Timestamp(Asia/Shanghai)를 붙인다.
    • 회사 구분 COMP_CD — SNKO/HALK별로 X-App-Id·CLIENT_ID·SALT가 다르다. 시크릿(client-secret/password)은 하드코딩이 아니라 @Value("${eir.snko.*}") / ${eir.halk.*}로 외부 주입된다 (EirService.java:67~73). 실값은 gitignore된 application.yaml에만 둔다.
    • 토큰 캐시 — Redis 기반 getValidTokenNew가 현행. ConcurrentHashMap 버전(getValidToken)은 "사용 X" 주석으로 비활성 (EirService.java:257).
    • 파일 전송은 FTP — FileDataService.downloadFileNas/connectFtp가 FtpProperty로 접속한다. ZIP 엔트리 쓰기 중 예외는 개별 파일 단위로 printStackTrace 후 건너뛴다(전체 실패로 번지지 않음) (PartnerController.java:159).
