    DSH (Dashboard) 도메인 코드 워크스루¶

    홈 대시보드(UserDashBoard) 달력의 개인 메모를 담당하는 도메인이다. 패키지 루트는 com.sinokor.vp.dsh, 테이블은 TB_CMS_USER_MEMO 하나다.

    이 도메인은 '복구'가 아니라 신설이다 (2026-08-31, PR #111)

    프론트에는 fnSelectMemo/fnSaveMemo 와 EScheduler 의 add·update·delete 배선이 이미 다 있었다. 그런데 그것들이 호출하는 /api/dsh/Home/* 는 V2 에도 레거시(sinokor-backend)에도 존재한 적이 없다. 레거시 프론트도 mounted() 의 fnSelectMemo() 가 똑같이 주석 처리돼 있었다. 즉 이 기능은 어느 쪽에서도 한 번도 동작한 적이 없고, 테이블만 남아 있었다(운영 데이터 0건). 그래서 DDL 없이 붙었다.

    1. 도메인 개요¶

    컨트롤러 1개 · 서비스 1개 · DAO 1개로 끝나는 가장 작은 도메인이다.

    flowchart LR
  FE[UserDashBoard 달력<br/>EScheduler] -->|/selectUserMemo| C[HomeController]
  FE -->|/saveMemo I·U·D| C
  C --> S[HomeService] --> D[(HomeDao)]
  D --- T[(TB_CMS_USER_MEMO)]

    경로가 /api/dsh/Home 인 이유 — 프론트가 이미 이 경로를 호출하도록 작성돼 있었다(레거시에서 넘어온 계약). 프론트를 고치지 않으려고 그대로 맞춘 것이지, 명명 규칙을 따른 것이 아니다 (src/main/java/com/sinokor/vp/dsh/controller/HomeController.java:23).

    엔드포인트 요청 응답
    POST /api/dsh/Home/selectUserMemo { QUERY_DATE } { MEMO_LIST: [...] }
    POST /api/dsh/Home/saveMemo { BATCH_FLAG: I\|U\|D, SAVE_MEMO_MAP } -

    2. 대표 흐름¶

    2-1. 조회 — 화면에 보이는 달 ±7일¶

    프론트는 달력에 보이는 달 안의 임의 날짜 하나를 QUERY_DATE 로 보낸다. 서비스가 이를 월 범위로 넓혀 조회한다.

    param.put( "FROM_DT", queryDate.withDayOfMonth( 1 ).minusDays( GRID_OVERFLOW_DAYS ).format( YYYYMMDD ) );
param.put( "TO_DT",   queryDate.withDayOfMonth( queryDate.lengthOfMonth() ).plusDays( GRID_OVERFLOW_DAYS ).format( YYYYMMDD ) );

    GRID_OVERFLOW_DAYS = 7 인 이유는 달력 그리드가 앞뒤 달을 물고 그려지기 때문이다. 1일이 수요일이면 그 주의 일~화는 전달 날짜이고, 그 칸의 메모도 보여야 한다 (HomeService.java).

    형식 변환도 여기서 한다 — 프론트는 js-joda LocalDate 를 그대로 직렬화해 ISO(yyyy-MM-dd) 로 보내는데 테이블은 VARCHAR2(8) yyyyMMdd 다. 매퍼에서 문자열을 주무르지 않도록 서비스에서 변환한다. QUERY_DATE 가 없거나 형식이 깨지면 오늘로 폴백한다 — 달력이 빈 화면으로 굳는 것보다 낫다.

    2-2. 저장 — BATCH_FLAG 로 I/U/D 분기¶

    DevExtreme Scheduler 의 add/update/delete 이벤트와 1:1 로 대응한다.

    if ( "I".equals( batchFlag ) )      homeDao.insertMemo( memo );
else if ( "U".equals( batchFlag ) ) homeDao.updateMemo( memo );
else if ( "D".equals( batchFlag ) ) homeDao.deleteMemo( memo );
else throw new IllegalArgumentException( "지원하지 않는 BATCH_FLAG: " + batchFlag );

    알 수 없는 플래그를 조용히 넘기지 않는다. 프론트는 I/U/D 만 보내므로 여기 오면 클라이언트가 깨진 것이다. 용어사전 코드를 쓰지 않은 이유는 messages.properties 가 비어 있고 문구가 DB 구동이라, 없는 코드를 쓰면 문구가 깨지기 때문이다.

    3. 알아둘 것¶

    MEMO_SN 채번 — 시퀀스도 PK 도 없다

    TB_CMS_USER_MEMO 에는 시퀀스가 없고 PK 제약도 없다(실측). 그래서 채번을 사용자별 MAX+1 로 한다.

    ( SELECT NVL(MAX(MEMO_SN), 0) + 1 FROM TB_CMS_USER_MEMO WHERE USER_ID = #{USER_ID} )

    따라서 MEMO_SN 은 사용자 안에서만 유일하다. 수정·삭제는 반드시 (USER_ID, MEMO_SN) 두 컬럼으로 걸어야 한다. MEMO_SN 단독으로 걸면 남의 메모를 지운다.

    USER_ID / CORP_CD 는 요청 본문에서 받지 않는다

    둘 다 컨트롤러에서 세션으로 덮어쓴다(HomeController.java:32,43-44). 클라이언트가 남의 USER_ID 를 실어 보내 조회·수정하는 것을 막기 위함이다. 이 도메인에 다른 엔드포인트를 추가할 때도 같은 규칙을 지킬 것.

    • selectUserDash(D-Day 차트)는 아직 없다. 프론트 fnSelectDash 는 그래서 주석 상태로 남아 있다. 추가한다면 이 도메인에 붙는 것이 맞다.
    • 조회 정렬은 START_DT, START_TM, MEMO_SN — 같은 날 여러 건일 때 표시 순서를 고정한다.
