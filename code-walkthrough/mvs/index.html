    MVS (Movement & Visibility Service) 도메인 코드 워크스루¶

    컨테이너 이동 현황을 조회하는 도메인이다. EQ No(컨테이너 번호)를 키로 LINER 외부 시스템의 컨테이너 이벤트 테이블을 조회해 위치·이동상태·운송업체·기사 등 가시성(visibility) 정보를 반환한다.

    1. 이 도메인이 하는 일¶

    mvs 패키지는 단일 기능(컨테이너 이동 이력 조회)으로 구성된 얇은 도메인이다.

    • 입력: 컨테이너 EQ No (EQ_NO)
    • 처리: LINER 시스템의 컨테이너 이벤트 테이블 LINER.T_OCEQ013을 조회하고, 코드성 컬럼(LOC_CD, MV_CD)을 스칼라 서브쿼리로 명칭 변환
    • 출력: 컨테이너 이동 레코드 목록을 LIST 키에 담아 반환

    구성 클래스는 컨트롤러 1, 서비스 1, DAO 1, 매퍼 XML 1개뿐이다.

    레이어 파일
    Controller src/main/java/com/sinokor/vp/mvs/controller/ContainerMovementController.java
    Service src/main/java/com/sinokor/vp/mvs/service/ContainerMovementService.java
    DAO src/main/java/com/sinokor/vp/mvs/dao/ContainerMovementDao.java
    Mapper src/main/resources/mapper/oracle/mvs/ContainerMovement-mapper.xml

    2. 대표 유스케이스: 컨테이너 이동 현황 조회¶

    POST /api/mvs/containerMovement/containerMovementList — 요청 바디에서 SEARCH 맵을 꺼내 그 안의 EQ_NO로 조회한다.

    sequenceDiagram
    participant FE as Frontend
    participant C as ContainerMovementController
    participant S as ContainerMovementService
    participant D as ContainerMovementDao
    participant DB as Oracle (LINER.T_OCEQ013)

    FE->>C: POST /containerMovementList<br/>{ SEARCH: { EQ_NO } }
    C->>S: containerMovementList(param)
    S->>S: param.getMap("SEARCH")
    S->>D: containerMovementList(paramMap)
    D->>DB: SELECT ... WHERE EQ_NO = #{EQ_NO}
    DB-->>D: List<DMap>
    D-->>S: List<DMap>
    S-->>C: List<DMap>
    C->>C: resultMap.put("LIST", list)
    C-->>FE: ResponseVo.of(resultMap).build()

    단계별 요지:

    1. 컨트롤러가 @RequestBody DMap param을 받아 그대로 서비스에 전달 (ContainerMovementController.java:25-28).
    2. 서비스가 param.getMap("SEARCH")로 검색 조건 맵을 추출해 DAO에 전달 (ContainerMovementService.java:19-20). 즉 실제 요청 형태는 { "SEARCH": { "EQ_NO": "..." } }.
    3. DAO는 @VpRepository 마커 인터페이스이며 메서드 시그니처만 선언 (ContainerMovementDao.java:8-11). 구현은 MyBatis XML.
    4. 매퍼가 LINER.T_OCEQ013을 EQ_NO로 조회 (ContainerMovement-mapper.xml:5-15).
    5. 결과 List<DMap>을 LIST 키에 넣어 ResponseVo.of(resultMap).build()로 응답 (ContainerMovementController.java:29-31).

    정확한 요청 페이로드

    컨트롤러는 param 전체를 받지만 서비스가 SEARCH 하위 맵만 사용하므로, 호출 시 검색 조건은 반드시 SEARCH 키 아래에 넣어야 한다 (ContainerMovementService.java:19).

    3. 핵심 엔드포인트¶

    메서드 경로 설명
    POST /api/mvs/containerMovement/containerMovementList SEARCH.EQ_NO 기준 컨테이너 이동 이력 목록 조회. 응답은 LIST 키에 레코드 배열

    베이스 경로는 클래스의 @RequestMapping("/api/mvs/containerMovement") (ContainerMovementController.java:17)와 메서드의 @PostMapping("/containerMovementList") (ContainerMovementController.java:24)의 결합이다.

    조회 컬럼¶

    매퍼가 반환하는 주요 컬럼 (ContainerMovement-mapper.xml:7-12):

    컬럼 의미(추정)
    EQ_NO 컨테이너(EQ) 번호 — 조회 키
    MV_CD / MV_NM 이동 상태 코드 / 명칭
    LOC_CD / LOC_NM 위치 코드 / 명칭
    TPSZ 컨테이너 타입·사이즈
    HAULIER 운송업체
    TRUCK_NO 트럭 번호
    BKNO 부킹 번호
    MARK 마크/비고
    DRIVER / DRV_TELNO 기사명 / 기사 연락처
    EQ_DATE_FULL 이벤트 일시(EQ_DATE 별칭)

    TODO: 컬럼 비즈니스 의미(특히 TPSZ, MARK, MV_CD 코드값)는 컬럼명 기반 추정이므로 LINER 데이터 정의로 확인 필요.

    4. 외부 연동 및 주의점¶

    LINER 외부 시스템 스키마 직접 조회

    이 도메인은 자체 테이블이 아니라 LINER 시스템 소유 테이블을 직접 SELECT한다 (ContainerMovement-mapper.xml:10-13).

    • LINER.T_OCEQ013 — 컨테이너 이벤트(이동) 본 테이블
    • LINER.T_OCCD102 — 위치 코드 명칭 변환용. NVL(LOC_ENM, LOC_NM)으로 영문명 우선, 없으면 한글명
    • LINER.T_OCCD106 — 이동상태(S_TYPE) → 명칭(S_MEAN) 변환용

    LINER 스키마/시노님에 대한 SELECT 권한이 전제이며, 외부 스키마 변경(컬럼·코드 테이블)에 직접 영향을 받는다.

    기타:

    • 코드명 변환을 조인이 아닌 스칼라 서브쿼리로 처리한다. T_OCCD102/T_OCCD106이 해당 코드에 대해 1행을 보장하지 않으면 런타임 오류 위험이 있다 (ContainerMovement-mapper.xml:10-11).
    • WHERE X.EQ_NO = #{EQ_NO} 단일 조건이라 EQ_NO가 비면 0건이다. 다른 검색 조건은 현재 미지원 (ContainerMovement-mapper.xml:14).
    • 이 엔드포인트는 application.yaml의 security.request-permit-all-mappings에 없으므로 인증 필요(공개 URL 아님).
    • 컨트롤러/서비스에 별도 검증·예외 처리가 없다. 잘못된 페이로드(SEARCH 누락 등) 처리는 DMap.getMap 동작에 의존한다 (ContainerMovementService.java:19).
