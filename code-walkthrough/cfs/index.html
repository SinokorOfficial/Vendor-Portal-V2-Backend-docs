    Container Freight Service (cfs) 도메인 코드 워크스루¶

    컨테이너 화물 서비스(CFS) Order Confirmation 정보를 조회하는 도메인이다. B/L No(부킹번호)와 사업부(회사/법인) 기준으로 TB_CFS_ORD_CON 테이블을 단건성 검색한다.

    1. 이 도메인이 하는 일¶

    • 단일 유스케이스: CFS 오더 컨펌(Order Confirmation) 목록 조회.
    • 컨트롤러 1개(CfsController) · 서비스 1개(CfsService) · DAO 1개(CfsDao) · 매퍼 1개(Cfs-mapper.xml)로 구성된 얇은 조회 전용 도메인이다.
    • 표준 레이어 컨벤션을 그대로 따른다: @RestController → @Service → @VpRepository DAO → MyBatis XML. 데이터 캐리어는 DMap, 응답은 ResponseVo.of(map).build().

    조회 대상 컬럼은 COMP_CD, CORP_CD, BK_NO, TPSZ, CNT, INP_DTM, INP_USR_ID 이다 (src/main/resources/mapper/oracle/cfs/Cfs-mapper.xml:6).

    2. 대표 유스케이스 흐름 — CFS Order Confirmation 조회¶

    POST /api/cfs/selectCfsOrdCon 요청 처리 흐름이다.

    sequenceDiagram
    participant FE as Frontend
    participant C as CfsController
    participant S as CfsService
    participant D as CfsDao
    participant M as Cfs-mapper.xml
    participant DB as Oracle (TB_CFS_ORD_CON)

    FE->>C: POST /api/cfs/selectCfsOrdCon (DMap)
    C->>S: selectCfsOrdCon(param)
    S->>S: param.getMap("SEARCH") 추출
    S->>D: selectCfsOrdCon(paramMap)
    D->>M: selectCfsOrdCon
    M->>DB: SELECT ... WHERE BK_NO/COMP_CD/CORP_CD
    DB-->>M: rows
    M-->>D: List<DMap>
    D-->>S: List<DMap>
    S-->>C: List<DMap>
    C->>C: resultMap.put("LIST", list)
    C-->>FE: ResponseVo.of(resultMap).build()

    단계 요약:

    1. CfsController.selectCfsOrdCon(@RequestBody DMap param) 가 요청 본문을 DMap으로 수신 (src/main/java/com/sinokor/vp/cfs/controller/CfsController.java:25).
    2. 서비스가 요청에서 SEARCH 하위 맵만 꺼내 DAO로 전달 — param.getMap("SEARCH") (src/main/java/com/sinokor/vp/cfs/service/CfsService.java:19).
    3. DAO 인터페이스 selectCfsOrdCon(DMap map) 가 MyBatis 매퍼로 위임 (src/main/java/com/sinokor/vp/cfs/dao/CfsDao.java:11).
    4. 매퍼가 TB_CFS_ORD_CON을 조회. 결과는 List<DMap> (src/main/resources/mapper/oracle/cfs/Cfs-mapper.xml:5).
    5. 컨트롤러가 결과를 LIST 키로 담아 ResponseVo로 반환 (src/main/java/com/sinokor/vp/cfs/controller/CfsController.java:29).

    요청 페이로드 구조

    서비스가 param.getMap("SEARCH")로 한 단계 내려간 맵을 사용하므로, 요청 JSON은 검색 조건을 SEARCH 객체 안에 중첩해야 한다. 응답은 LIST 키 아래 결과 배열을 담는다.

    3. 핵심 엔드포인트¶

    메서드 경로 설명
    POST /api/cfs/selectCfsOrdCon CFS Order Confirmation 목록 조회. SEARCH 맵의 BK_NO(B/L No)·COMP_CD(회사)·CORP_CD(법인) 조건으로 TB_CFS_ORD_CON 검색, LIST로 반환

    베이스 경로 /api/cfs 는 클래스 레벨 @RequestMapping("/api/cfs") 에 선언 (src/main/java/com/sinokor/vp/cfs/controller/CfsController.java:17).

    4. 외부연동 · 주의점¶

    • 외부 시스템 연동 없음. EIR/SIPG/FTP 등 외부 호출이나 별도 시크릿 의존이 없는 순수 Oracle 단건 조회 도메인이다.

    • 검색 조건 3개 모두 AND 필수: 매퍼가 BK_NO, COMP_CD, CORP_CD 를 모두 #{...} 바인딩으로 AND 결합한다 (src/main/resources/mapper/oracle/cfs/Cfs-mapper.xml:9). 동적 <if> 분기가 없어 세 값이 모두 채워져야 의미 있는 결과가 나오며, 빠진 값은 null로 바인딩돼 매칭에서 빠진다.

      공통코드 주입 미적용

      서비스가 SEARCH 맵을 그대로 DAO에 넘기므로 COMP_CD/CORP_CD(사업부)는 프론트가 채워 보낸 값에 의존한다. 서버단에서 세션 기반 사업부를 강제 주입하지 않는다.

    • 인증 필요: /api/cfs/** 는 security.request-permit-all-mappings(공개 URL 목록)에 없어 일반 인증 보호 대상이다.

    • 확장은 매퍼 위주: 현재 selectCfsOrdCon 1개 쿼리만 존재. 조건 추가/페이징 등 변경은 대부분 Cfs-mapper.xml에서 이루어진다(타입 DTO 미사용, DMap 캐리어 유지).
