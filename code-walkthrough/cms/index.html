    CMS (Content Management System) 도메인 코드 워크스루¶

    com.sinokor.vp.cms 패키지는 포털 운영에 필요한 메타/관리 기능을 모은 도메인이다. 메뉴·권한·역할·부서 트리, 사용자 관리, 그리드 레이아웃 커스터마이징, 에러/로그인/방문 로그, JWT 발급 관리, 자동채번(Autono) 규칙, 공통 팝업 조회를 담당한다.

    1. 도메인 개요¶

    소스 트리는 기능별 하위 패키지로 나뉜다. 모든 컨트롤러는 ExtendBaseController를 상속해 getSession(), getUserId(), getCorpCd(), getLocale() 등 세션 헬퍼를 사용하고, 데이터 캐리어는 전 구간 DMap, 응답은 ResponseVo.of(...).build() 컨벤션을 따른다.

    하위 패키지 역할 대표 클래스
    cms.comm 공통/메뉴/사용자/역할·메뉴 권한/화면/JWT/에러로그/그리드 레이아웃 CmsCommonController, CmsUserMgtController, CmsMenuMgtController, CmsRoleMenuMgtController, CmsScreenMgtController, CmsJwtMgtController, CmsErrorLogController
    cms.autono 자동채번 규칙 엔진(런타임 채번) AutonoRuleHandler, AutonoRuleCommon, AutonoRuleDao
    cms.setting 자동채번 규칙 마스터 관리/카운트 CmsAutonoRuleMgtController, CmsAutonoCountController
    cms.log 로그인 로그·방문 로그·로그 목록·관측성 대시보드(Azure Monitor 실시간 조회) CmsLoginLogController, CmsVisitLogController, CmsLogListController, CmsAzureLogController
    cms.popup 공통 코드 검색 팝업(항구/선박/고객/통화 등) CmsCommonPopupController, CmsDocumentPopupController, CmsHistoryPopupController

    엔드포인트 경로 주의

    실제 매핑 경로는 컨트롤러 클래스의 @RequestMapping을 그대로 따른다. 예를 들어 사용자 목록은 /api/cms/comm/cmsUserMgt/selectList이며(cms/comm/controller/CmsUserMgtController.java:20,28), 짧은 형태(/api/cms/user/...)가 아니다. 아래 표는 소스에서 확인된 실제 경로다.

    DAO는 인터페이스만 두고(@VpRepository 마커, @Mapper 아님), SQL은 resources/mapper/oracle/cms/<하위패키지>/*-mapper.xml에 둔다. 매퍼 namespace는 DAO FQCN과 일치한다(예: mapper/oracle/cms/comm/CmsCommon-mapper.xml:4).

    2. 대표 유스케이스 흐름¶

    2-1. 그리드 레이아웃 저장 (사용자별 화면 커스터마이징)¶

    ag-grid 컬럼 상태를 사용자/법인/메뉴/그리드 단위로 저장한다. 신규/수정은 레이아웃명 존재 여부로 분기한다.

    sequenceDiagram
    participant FE as Frontend
    participant C as CmsCommonController
    participant S as CmsCommonService
    participant D as CmsCommonDao (MyBatis)
    FE->>C: POST /api/cms/comm/gridLayout/save
    C->>C: param.put(CORP_CD, USER_ID)  // 세션에서 주입
    C->>S: saveGridLayout(param)
    S->>D: validGridLayout(param)
    D-->>S: LAYOUT_NM ("NULL" or 기존명)
    alt "NULL" == 결과
        S->>D: insertGridLayout(param)
    else 기존 존재
        S->>D: updateGridLayout(param)
    end
    S-->>C: gridLayoutName
    C-->>FE: ResponseVo.of(name)
    • 진입: CmsCommonController.saveGridLayout — CORP_CD/USER_ID를 세션에서 채워 서비스로 전달 (cms/comm/controller/CmsCommonController.java:30-38).
    • 분기: CmsCommonService.saveGridLayout — validGridLayout 결과가 "NULL"이면 insert, 아니면 update (cms/comm/service/CmsCommonService.java:174-189).
    • 조회 시(selectGridLayout)는 selectColumnState와 selectGridLayout를 각각 불러 CODE(=LAYOUT_NM) 기준으로 COLUMN_STATE를 병합한다 (CmsCommonService.java:157-172). 대상 테이블은 TB_CMS_GRID_LAYOUT (mapper/oracle/cms/comm/CmsCommon-mapper.xml:131-137,160-166).

    2-2. 사용자 저장 (Facade로 다중 그리드 일괄 처리)¶

    사용자 한 건 저장 시 본정보 + 법인관계 + 역할 + 항구 + 권한 트리를 한 트랜잭션으로 묶는다. 컨트롤러는 CmsUserMgtFacade에 위임한다.

    1. CmsUserMgtController.save → USER_ID(=작업자)를 주입하고 cmsUserMgtFacade.save(param) 호출 (cms/comm/controller/CmsUserMgtController.java:53-59).
    2. CmsUserMgtFacade.save (@Transactional) — param에서 MAIN/CORP_GRID/ROLE_GRID/PORT_GRID/AUTH_TREE를 꺼내 서비스 메서드를 순차 호출 (cms/comm/facade/CmsUserMgtFacade.java:17-28).
    3. CmsUserMgtService.save — validUserId의 VALID_CNT로 INSERT/UPDATE 플래그 결정, BatchFlag 상수 사용 (cms/comm/service/CmsUserMgtService.java:101-121). 역할/항구는 행별 BATCH_FLAG(INSERT/UPDATE/DELETE)로 분기하고, 권한은 deleteAuth 후 insertAuth로 전체 치환한다 (CmsUserMgtService.java:146-178).

    비밀번호 변경은 AdminService 위임

    changePassword는 CMS 내부가 아니라 adminService.findPassword(USER_ID, EMAIL)로 처리되며 메일 발송을 수반한다(MessagingException/IOException throws) (CmsUserMgtController.java:76-80).

    4. 자동채번(Autono) — 두 갈래 구현 주의¶

    CMS에는 채번 로직이 두 가지 존재하며 혼동하기 쉽다.

    • 레거시 방식 — CmsCommonService.createAutoNo: autoNoTp(JOB_NO/HBL_NO/INV_NO/BKG_NO 등)를 switch로 하드코딩해 prefix를 만들고, TB_CMS_AUTONO_RULE에서 시퀀스 자리수(AUTONO_SEQ)를 조회한다. 지사에 룰이 없으면 selectCmsCommonAutoNoSeqUpper로 상위 법인(TB_MDM_CORP.UPPER_CORP_CD) 룰을 승계한다. 채번 카운트는 TB_CMS_AUTONO에 MERGE로 증가시킨다 (CmsCommonService.java:26-155; SQL CmsCommon-mapper.xml:6-69).
    • 규칙 엔진 방식 — AutonoRuleCommon(AutonoRuleHandler 구현): prefix를 코드가 아니라 DB 규칙(TB_* 규칙 테이블, AutonoRuleDao)에서 읽는다. PrefixTp가 STATIC/DYNAMIC/DATE/SEQ로 구성되며, SEQ_AREA 자리를 시퀀스로 치환한다. @Transactional(propagation = REQUIRES_NEW)로 별도 트랜잭션에서 채번하며, 룰이 없으면 RuntimeException("자동 채번 룰이 세팅 되지 않았습니다.")을 던진다 (cms/autono/handler/AutonoRuleCommon.java:39-110). 로그인 사용자는 SecurityContextHolder에서 LoginUser로 획득 (:152-159).
    sequenceDiagram
    participant Caller
    participant H as AutonoRuleCommon
    participant D as AutonoRuleDao
    Caller->>H: createAutono(moduleDiv, autonoTp, dataMap)
    H->>D: selectRule(corpCd, moduleDiv, autonoTp)
    D-->>H: List<RuleResult>  // STATIC/DYNAMIC/DATE/SEQ
    H->>H: prefix 조립 (SEQ는 SEQ_AREA placeholder)
    H->>D: selectSequence(prefix)
    D-->>H: 직전 SN(없으면 null)
    H->>D: insert/update (SN+1, REQUIRES_NEW)
    H-->>Caller: LPAD 포맷 적용된 채번 문자열

    신규 코드의 채번

    신규 모듈은 AutonoRuleHandler 규칙 엔진을 사용하는 것이 의도된 방향이다. CmsCommonService.createAutoNo의 switch 분기는 특정 채번타입에 종속(예: HBL_NO/BKG_NO는 CORP_PREFIX 필수)되어 있으니 신규 타입 추가 시 그대로 확장하지 말 것.

    5. 외부 연동·주의점¶

    • 세션 의존: 거의 모든 컨트롤러가 getSession().getCorpCd()/getUserId()로 법인·사용자를 주입한다. 세션은 Redis(2h)에 저장된다. 인증 없는 호출은 채번 엔진에서 LoginUser가 null이 되어 NPE 위험이 있다 (AutonoRuleCommon.java:44-46,152-159).
    • 권한 트리 표기: 역할-메뉴/버튼 권한 트리는 TREE_PATH를 ★(U+2605) 구분자로 잘라 LVL1..LVLn 컬럼으로 펼친다. 프런트의 트리 그룹핑(GROUP)이 이 규약에 의존한다 (CmsRoleMenuMgtController.java:50-95, CmsRoleButtonMgtController.java:48-65).
    • 레이아웃 복사 검증: copyGridLayout은 대상 사용자 존재(validUser)와 레이아웃 중복을 검사하고, 중복 시 "중복 된 레이아웃이 존재 합니다" 오류를 던진다 (CmsCommonService.java:191-223).
    • 권한 전체 치환: 사용자 권한 저장은 deleteAuth 후 insertAuth로 전량 교체한다. "권한 1개 이상 필수"(MSG000239) 검증은 현재 주석 처리되어 비활성 상태다 (CmsUserMgtService.java:167-178).
    • 관측성 대시보드 KQL 인젝션 방어: CmsAzureLogService에서 URL_PART 등 클라이언트 입력은 kqlEscape 필수다. 범용 KQL 통과 API는 워크스페이스의 nginx 액세스로그(SSO 토큰이 실린 URL·사용자 IP)가 유출 경로가 되므로 의도적으로 두지 않았다 (cms/log/service/CmsAzureLogService.java:523-531,597).
    • 응답 일관성 미흡: 일부 핸들러는 ResponseVo 대신 void를 반환하거나 return null을 한다(예: CmsCommonController.saveHistory, CmsMenuMgtController.save, CmsScreenMgtController.save). 프런트 후처리 시 빈 응답을 가정해야 한다.
