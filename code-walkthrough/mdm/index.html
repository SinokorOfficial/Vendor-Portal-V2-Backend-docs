    MDM (Master Data Management) 도메인 코드 워크스루¶

    시스템 전반에서 참조하는 기초 데이터(마스터) 중 V2 화면이 실제로 쓰는 법인(Corp), 공지사항을 관리하는 도메인이다.

    2026-10 정리

    메뉴가 꺼져 있거나 메뉴가 없던 화면(항구, 국가, 통화, 환율, HS코드, 세관, 컨테이너, 상용구, 포장단위, 관세, 창고, 고객, 조직)의 백엔드는 Infra #80 에서 삭제했다. 고객 마스터의 외부 CRM(ulogitech.com) 동기화도 함께 사라졌다.

    운임 코드 관리(/api/mdm/code/mdmFreightMgt)도 프론트 화면 삭제 결정에 따라 같은 이슈에서 백엔드를 삭제했고, 이로써 code 하위 패키지는 없어졌다. 공통 팝업의 운임 검색(/api/cms/popup/cmsCommonPopup/selectFreight)은 그대로 남아 운임 테이블(TB_MDM_FRT 등)을 계속 읽는다.

    1. 도메인 개요¶

    패키지 루트는 com.sinokor.vp.mdm 이고, 기능별 하위 패키지로 나뉜다.

    하위 패키지 책임 대표 클래스
    organization 법인(Corp) 마스터, 법인 트리/관계 MdmCorpMgtController
    other 공지(Notice) MdmNoticeController

    공통 레이어 규약(레포지토리 컨벤션과 동일):

    • 컨트롤러는 모두 ExtendBaseController를 상속해 세션 헬퍼(getUserId(), getCorpCd())를 사용한다 — ExtendBaseController.java:28, ExtendBaseController.java:32.
    • 데이터 캐리어는 DMap, 응답은 ResponseVo.of(...).build().
    • DAO는 @VpRepository 인터페이스 + resources/mapper/oracle/mdm/<module>/*-mapper.xml(MyBatis XML).
    • 입력/수정/삭제 분기는 행(row)의 BATCH_FLAG(INSERT/UPDATE/DELETE) 또는 사전 valid* 카운트 쿼리로 결정한다.

    Note

    컨트롤러 URL은 organization이 /api/mdm/organization/..., other는 /api/mdm/other/... 로 패키지 구조를 그대로 따른다.

    2. 대표 유스케이스¶

    메인 + 자식 그리드를 한 번에 저장하는 대표 예는 법인(MdmCorpMgtService.save, 은행 BANK_GRID 와 법인 관계 CORP_GRID)이다.

    3. 핵심 엔드포인트¶

    모든 엔드포인트는 POST이며 본문은 JSON(DMap)이다. 회사 관리와 공지 저장의 허용 역할은 보안 문서 한 곳에 적는다.

    경로 설명 근거
    /api/mdm/organization/mdmCorpMgt/selectTree 법인 트리 조회 MdmCorpMgtController.java:22
    /api/mdm/organization/mdmCorpMgt/select /selectCorpRel /save /delete 법인 단건/관계/저장/삭제 :33,41,47,55
    /api/mdm/other/mdmNotice/selectList /select /save /delete 공지 목록/단건/저장/삭제 MdmNoticeController.java:20,29,38,45
