    MDM (Master Data Management) 도메인 코드 워크스루¶

    운송사·고객·조직·항구·국가·HS코드·선박·환율·세관 등 시스템 전반에서 참조하는 기초 데이터(마스터)를 관리하는 도메인이다. 외부 CRM(ulogitech.com) 동기화와 사업자등록번호 중복 검증, 가격표(Pricing) 엑셀 업로드 등 부가 기능을 포함한다.

    1. 도메인 개요¶

    패키지 루트는 com.sinokor.vp.mdm 이고, 기능별 하위 패키지로 나뉜다.

    하위 패키지 책임 대표 클래스
    code 코드성 마스터(운송사·항구·국가·선박·환율·HS코드·세관·통화·관세·창고 등) MdmPortMgtController 외
    customer 고객(거래처) 마스터 + 담당자/은행/권한 + CRM 동기화 MdmCustomerMgtController, MdmCustomerMgtFacade
    organization 조직(법인) 마스터, 법인 트리/관계 MdmCorpMgtController, MdmOrganizationMgtController
    other 공지(Notice) MdmNoticeController
    user 사용자별 회사/거래처 설정 MdmUserSettingController

    공통 레이어 규약(레포지토리 컨벤션과 동일):

    • 컨트롤러는 모두 ExtendBaseController를 상속해 세션 헬퍼(getUserId(), getCorpCd())를 사용한다 — ExtendBaseController.java:28, ExtendBaseController.java:32.
    • 데이터 캐리어는 DMap, 응답은 ResponseVo.of(...).build().
    • DAO는 @VpRepository 인터페이스 + resources/mapper/oracle/mdm/<module>/*-mapper.xml(MyBatis XML).
    • 입력/수정/삭제 분기는 행(row)의 BATCH_FLAG(INSERT/UPDATE/DELETE) 또는 사전 valid* 카운트 쿼리로 결정한다.

    Note

    code 모듈의 컨트롤러 URL은 /api/mdm/code/..., organization은 /api/mdm/organization/..., other는 /api/mdm/other/... 로 패키지 구조를 그대로 따른다. 단, 고객(customer)만 예외로 /api/mdm/mdmCustomerMgt 이다(MdmCustomerMgtController.java:17).

    2. 대표 유스케이스¶

    2-1. 항구(Port) 코드 저장 — 표준 마스터(그리드) 저장 흐름¶

    save는 그리드(PORT_GRID)를 한 요청으로 받아 행별 BATCH_FLAG(INSERT/UPDATE/DELETE) 로 분기한다. INSERT 행은 사전 존재 검사(validPort) 후 삽입한다.

    sequenceDiagram
    participant FE as Frontend
    participant C as MdmPortMgtController
    participant S as MdmPortMgtService
    participant D as MdmPortMgtDao (MyBatis)
    FE->>C: POST /api/mdm/code/mdmPortMgt/save
    C->>C: param.put("USER_ID", getUserId())
    C->>S: save(param)
    loop PORT_GRID 각 행 (BATCH_FLAG)
        alt INSERT
            S->>D: validPort(row)  // 중복이면 errorMessage throw
            S->>D: insert(row)
        else UPDATE
            S->>D: update(row)
        else DELETE
            S->>D: delete(row)
        end
    end
    C-->>FE: ResponseVo.of().build()

    근거: 컨트롤러 MdmPortMgtController.java:33(save → mdmPortMgtService.save), 서비스 MdmPortMgtService.java:34-55(PORT_GRID 행별 BATCH_FLAG 분기), 검증 MdmPortMgtService.java:26(validPort — 중복 시 errorMessage throw).

    Note

    이 "그리드 + 행별 BATCH_FLAG" 패턴이 국가(MdmCountryMgtController)·환율(MdmExrateMgtController) 등 대부분의 코드 마스터에 반복된다. 메인 + 자식(2테이블) 변형은 고객(§2-2)·조직(MdmCorpMgtController)을 참고.

    2-2. 고객(Customer) 저장 — Facade로 다중 자식 묶음 처리¶

    고객은 메인 외에 담당자(PIC)·은행(BANK)·권한(AUTH) 그리드를 함께 저장한다. 컨트롤러는 MdmCustomerMgtFacade에 위임하고, Facade가 @Transactional로 묶어 코드 자동채번·각 자식 저장·변경이력 저장을 한 트랜잭션으로 처리한다.

    sequenceDiagram
    participant FE as Frontend
    participant C as MdmCustomerMgtController
    participant F as MdmCustomerMgtFacade (@Transactional)
    participant S as MdmCustomerMgtService
    participant AN as AutonoRuleHandler
    participant CMS as CmsCommonService
    FE->>C: POST /api/mdm/mdmCustomerMgt/save
    C->>F: save(param)  (USER_ID/CORP_CD/DEPT_CD 주입)
    alt 신규(CUST_CD 공백)
        F->>AN: createAutono("MDM","CUST_CD")
    end
    F->>S: saveMain(MAIN, userId)
    S->>S: validateCustomer → INSERT or UPDATE
    F->>S: savePic / saveBank / saveAuth (각 BATCH_FLAG 분기)
    F->>CMS: saveHistory(변경이력)
    C-->>FE: ResponseVo.of(param)

    근거: MdmCustomerMgtController.java:60-69(save → Facade 위임), MdmCustomerMgtFacade.java:44-76(트랜잭션 경계, createAutono로 신규 채번, saveMain/savePic/saveBank/saveAuth + saveHistory). 메인 저장의 INSERT/UPDATE 분기는 validateCustomer의 VALID_CNT로 결정한다(MdmCustomerMgtService.java:87-109).

    조회 측 selectDetail도 Facade(select)에서 변경이력·메인·담당자·은행·권한 그리드를 한 번에 묶어 반환한다(MdmCustomerMgtFacade.java:23-42).

    검증 로직:

    • 은행 계좌번호 중복 검사 — 같은 계좌번호가 다른 BANK_SEQ로 들어오면 MSG000014("중복된 계좌번호") 예외(MdmCustomerMgtService.java:138-149).
    • 담당자 권한 중복 검사 — validateAuth로 MSG000014("중복된 권한") 예외(MdmCustomerMgtService.java:187-194).
    • 사업자등록번호 검증 — validateBizReg는 기존 값과 동일하면 0, 변경됐으면 DB 중복 카운트를 반환(MdmCustomerMgtService.java:196-204).

    4. 외부 연동 · 주의점¶

    CRM 동기화 (crmSync)¶

    MdmCustomerMgtService.crmSync는 외부 CRM에서 거래처 목록을 받아 고객(CUSTOMER)과 법인(CORP)을 함께 갱신한다 — MdmCustomerMgtService.java:210-377.

    • 연동 대상: WebClient로 http://ulogitech.com/adm/contract/custApi?use_yn=Y&udt_dtm={STD_YMD} 호출, 응답은 XML Content-Type, 본문은 JSON 문자열을 List<DMap>으로 역직렬화(getCrmApi :380-389, getWebClient :391-406).
    • 타임아웃: connect 3초, read 5초, write 60초로 하드코딩(:392-399).
    • 국가코드 매핑: selectCrmContryCodeMpng로 CRM 국가코드를 내부 코드로 매핑, 매핑이 없으면 원본 코드, 국가정보 누락 시 KR 기본값(:256-268, 매퍼 MdmCustomerMgt-mapper.xml:536).
    • 고객 upsert: 기존 고객 존재 시 update+saveCustType, 없으면 insert+saveCustType(:284-304). 이어서 MdmCorpMgtService로 법인도 동일하게 갱신/신규(UPPER_CORP_CD=CUSTKR, HQ_CORP_CD=CUSTHQ, ORG_LVL=LB 등 고정값)(:316-365).
    • 전 과정은 @Transactional이며 건마다 변경이력(CmsCommonService.saveHistory, NEW_VAL="CRM SYNC")을 남긴다(:307-314).

    Warning

    CRM 호스트(http://ulogitech.com)와 타임아웃 값이 소스에 하드코딩되어 있다(MdmCustomerMgtService.java:381, :392-398). 환경 분리/시크릿 정책 관점에서 @Value 외부화 후보다. 평문 HTTP 호출인 점도 유의.

    사업자등록번호 검증¶

    validateBizReg는 원본값과 동일하면 검증을 건너뛰고(0 반환), 값이 바뀐 경우에만 DB 중복 카운트를 조회한다(MdmCustomerMgtService.java:196-204, DAO MdmCustomerMgtDao.java:50). CRM 동기화 시에는 business_no의 하이픈(-)을 제거해 저장한다(:279, :294).

    공통 주의점¶

    • 고객 모듈만 URL 규칙이 다르다(/api/mdm/mdmCustomerMgt). 코드 작성 시 패키지명에서 code/를 유추하지 말 것(MdmCustomerMgtController.java:17).
    • 세션 주입: 저장/동기화 시 컨트롤러가 USER_ID, CORP_CD, DEPT_CD를 세션에서 채워 넣는다(예: MdmCustomerMgtController.java:62-64, :73-75). DEPT_CD에 CORP_CD를 넣는 부분은 의도된 현행 동작.
    • 페이징: 목록 조회는 PageHelper(PageHelper.startPage)로 처리하며 응답에 PAGE_LENGTH/PAGE_TOTAL을 포함한다(MdmCustomerMgtService.java:50-58).
