    관리자(Admin) 도메인 코드 워크스루¶

    com.sinokor.vp.admin 패키지는 인증/세션, 권한 기반 메뉴 구성, 비밀번호 변경/초기화, 아이디 찾기, 파일 업로드/다운로드, 웹푸시 등록, 에러 로그 적재 등 포털 전반의 공통 기능을 담당한다. Spring Security가 실제 로그인을 처리하고, 컨트롤러는 세션 조회·메뉴맵·계정 보조 기능을 제공한다.

    1. 이 도메인이 하는 일¶

    영역 담당 클래스 설명
    인증/세션 AdminService(UserAuthenticationService 구현) loadUserByUsername으로 LoginUser 적재, 로그인 성공/실패/로그아웃 로그 적재
    메뉴/권한 AdminService + AdminController 역할(ROLE) 기반 메뉴·버튼·팝업·MY-MENU 계층 구성
    계정 보조 AdminService 비밀번호 변경, 임시 비밀번호 발송(아이디/비번 찾기), 비밀번호 이력 검증
    공통코드/채번 CodeController + CodeService 공통코드·언어코드·법인코드 조회, 자동채번(AutonoRuleHandler)
    파일 FileDataController + FileDataService 업로드/다운로드, Base64 이미지, 엑셀 템플릿 생성
    웹푸시 WebPushController + WebPushService 브라우저 구독 정보(endpoint/keys) 등록
    에러 로그 AdminService(WriteErrorCodeService 구현) 전역 예외를 TB_CMS_ERROR_LOG에 적재하고 에러코드 헤더 반환

    레이어는 프로젝트 컨벤션대로 @RestController(ExtendBaseController 상속) → @Service → @VpRepository DAO → resources/mapper/oracle/admin/*-mapper.xml이며, 데이터 캐리어는 DMap, 응답은 ResponseVo.of(...).build()를 사용한다.

    로그인 엔드포인트 주의

    실제 로그인 URL은 컨트롤러 메서드가 아니라 Spring Security 필터가 처리하는 POST /api/login 이다(application.yaml:81 security.login-url). AdminController의 POST /api/session(AdminController.java:48)은 이미 인증된 세션 정보를 반환할 뿐 로그인 자체가 아니다.

    2. 대표 유스케이스¶

    2-1. 로그인 (Spring Security)¶

    LoginAuthenticationProcessingFilter가 /api/login(AntPathRequestMatcher)을 가로채고, AdminService.loadUserByUsername이 사용자 정보를 적재한다.

    sequenceDiagram
    participant C as Client
    participant F as LoginAuthenticationProcessingFilter
    participant P as LoginUserDaoAuthenticationProvider
    participant S as AdminService
    participant D as AdminDao / Admin-mapper.xml

    C->>F: POST /api/login (application/json)
    F->>F: Content-Type / Content-Length 방어
    F->>P: authenticate(authentication)
    P->>S: loadUserByUsername("userId=:=corpCd=:=...")
    S->>D: selectUser(USER_ID, CORP_CD)
    D-->>S: 사용자/법인/고객 정보(DMap)
    S->>D: selectRoleId(...) / selectCorpRelMgt(...)
    S-->>P: LoginUser(UserDetails)
    P->>P: 마스터PW 비교 또는 BCrypt 검증
    P-->>F: 인증 성공
    F->>S: loginSuccess() → insertLoginLog("S01"), initPasswordFailCount()
    F-->>C: 세션 저장(HttpSession→Redis), 응답
    • 입력 username은 =:=(AdminService.java:79 SEPARATOR) 구분자로 userId / corpCd / ssoCustCd / systemDiv / ...를 담는다(getUserInfoVo, AdminService.java:516).
    • 비밀번호 검증은 LoginUserDaoAuthenticationProvider.authenticate(LoginUserDaoAuthenticationProvider.java:52). 환경변수 MASTER_PASSWORD가 설정되어 있고 입력값이 일치하면 BCrypt 검증을 건너뛰는 마스터 로그인이 동작한다(LoginUserDaoAuthenticationProvider.java:68).
    • 사전 체크에서 loginFailCnt >= 5면 로그인 차단(AdminService.getPreChecker, AdminService.java:565), 유효기간(START_DT/END_DT) 만료 시에도 거부(validateUserDate, AdminService.java:551).

    • 실패 시 loginFailure가 사유를 판별해 TB_CMS_LOGIN_LOG.LOGIN_DIV 에 코드를 남긴다(AdminService.resolveLoginDiv).

      코드 사유 판별 방법 사용자에게 나가는 문구
      E01 비밀번호 오류 BadCredentialsException (+ 실패횟수 증가) Password does not match.
      E02 계정 없음 selectUser null + selectUserUseYn 도 null The user ID does not exist.
      E03 비활성 계정(USE_YN='N') selectUser null + selectUserUseYn 이 값 반환 This account is disabled. Please contact the administrator.
      E04 5회 실패 잠금 LoginAuthenticationException (getPreChecker 가 던지는 유일한 타입) 5 failed logins, please proceed to find the password.
      E05 유효기간 만료 validateUserDate 가 심은 사유 코드 The account validity period has expired. Please contact the administrator.

      E02/E03/E05 는 LoginFailureReasonException(순수 RuntimeException)에 코드를 실어 보내고, loginFailure 가 cause 체인에서 꺼낸다. 이 예외를 WebException이나 AuthenticationException 하위로 만들면 사용자 문구가 바뀐다 — 전자는 WebExceptionTranslator 가 409/errDiv 01 로, 후자는 AuthenticationExceptionTranslator 폴백이 "You do not have the necessary permissions." 로 처리한다. 현재는 LoginUserDaoAuthenticationProvider 가 InternalAuthenticationServiceException 으로 감싸므로 401 + 위 문구가 그대로 나간다.

      판별 실패 시 기존 동작대로 E02 로 폴백한다. loginFailure 에서 예외가 새면 인증 필터 밖으로 전파돼 401 대신 Tomcat 기본 500 이 나가므로, 분류 로직은 절대 예외를 던지지 않는다.

    LOGIN_DIV 코드마스터 — 운영 등록 완료(2026-08-25)

    CmsLoginLog 화면의 명칭·검색 콤보는 100% 코드마스터(TB_CMS_CD_DTL, MSTR_CD='LOGIN_DIV') 구동이다(화면 코드 수정은 불필요 — 미등록 코드는 ValueFormatter.printName 이 undefined 를 반환해 그리드에 raw 코드가 뜨고 검색 콤보에서 빠진다). 운영에 E01~E05 등록 완료(E01 비밀번호 오류 / E02 계정 없음 / E03 비활성 계정 / E04 5회 잠금 계정 / E05 유효기간 만료 계정). 레거시 partner 와 같은 DB 를 보므로 이 1회 등록으로 양쪽에 반영된다.

    • ⚠️ .100(개발) 에는 미등록 — 로컬에서 이 화면을 보면 raw 코드로 표시된다.
    • ⚠️ E02 라벨 변경이 과거 데이터에 소급된다 — 종전 E02("사용자 권한 오류")는 비밀번호 오류를 뺀 모든 실패를 뭉뚱그린 코드였는데 이제 "계정 없음"으로 표시된다. PR #105 배포 이전에 쌓인 7,264건은 실제로는 비활성·잠금·만료가 섞여 있다(사용자 승인 후 진행).
    • ⚠️ CodeService.cacheCodeMap 에는 무효화 로직이 없다 — 코드를 등록해도 브라우저 강력 새로고침 전에는 반영되지 않는다.
    • 엑셀 내보내기는 valueFormatter 를 우회하므로 raw 코드로 나간다(기존과 동일).

    레거시에도 같은 패치를 커밋해 뒀으나(빌드·배포는 별도), 배포 전까지 레거시는 E01/E02 만 기록한다. 컷오버 기간에는 LOGIN_MSG='Login at V2' 로 유입 시스템을 구분해서 읽어야 한다.

    S01(LOGIN_MSG='Login at V2')은 V2 URL 직접 로그인 + 레거시→V2 SSO 유입을 모두 포함한다(PR #106). SSO 유입은 JwtAuthenticationFilter 가 적재하며, 둘을 구분하는 마커는 두지 않았다 — 목적이 "V2 에 접속한 사용자 파악"이기 때문이다. "아직 레거시 주소로 들어오는 사용자"는 레거시 행(LOGIN_MSG IS NULL)으로 센다.

    세션 영속 명시 설정

    Spring Security 6에서 AbstractAuthenticationProcessingFilter 기본 컨텍스트 저장소가 비저장으로 바뀌어, 필터에 HttpSessionSecurityContextRepository를 명시 설정해야 Redis 세션(SINOKORSESSION)으로 인증이 유지된다(WebSecurityBeansConfiguration.java:89).

    2-2. 메뉴맵 조회 (POST /api/menuMap)¶

    로그인 후 화면 구성을 위해 사용자 권한 기준 메뉴 트리를 조립한다.

    1. AdminController.menuMap(AdminController.java:156): 세션에서 userId/corpCd, 로케일 언어를 추출.
    2. adminService.selectMenuAndLevelList(...)(AdminService.java:316): selectMenuAndLevelList(메뉴) + selectMenuButtonList(버튼)를 조회해 joinMenuListAndButtonList로 메뉴별 버튼을 병합. SQL은 TB_CMS_MENU 기반(Admin-mapper.xml:168).
    3. 응답 DMap에 4종을 담아 반환:
    4. menuMap — 실행 가능한 메뉴(MENU_PATH 보유)를 MENU_ABBR 키로 맵핑(collectExecuteMenuMap, AdminService.java:394).
    5. menuHierarchyList — DISP_YN='Y'만 골라 UPPER_MENU_ID 기준 재귀로 계층/네비게이션 생성(createHierarchyMenuList, AdminService.java:399).
    6. myMenuList — 즐겨찾기 메뉴(selectMyMenuList, Admin-mapper.xml:364). 정렬은 TB_CMS_USER_MENU.MENU_SEQ — 아래 §2.1 참고.
    7. popupMap — 팝업 메뉴 맵(selectPopupMenuMap, AdminService.java:323).
    8. ResponseVo.of(data).build()로 응답.

    연관: POST /api/registMyMenu(즐겨찾기 토글, AdminService.java:351), POST /api/reorderMyMenu(전체 삭제 후 재삽입, AdminService.java:373), POST /api/insertVisitLog(메뉴 방문 로그, TB_CMS_VISIT_LOG).

    2.1 즐겨찾기(MY-MENU) 순서 — TB_CMS_USER_MENU¶

    목록 순서는 표시 순서일 뿐 아니라 로그인 직후 랜딩 화면을 정한다(프론트 menuAuthGuard 가 첫 항목으로 이동, ADMIN 역할 제외).

    • 정렬 기준 — MENU_SEQ 오름차순(Admin-mapper.xml:399). 사용자가 사이드메뉴 즐겨찾기 편집에서 끌어놓은 순서.
    • 채번 — insertMyMenu(Admin-mapper.xml:429)가 사용자별 MAX(MENU_SEQ)+1 로 매기므로 신규 등록은 항상 맨 뒤.
    • 순서 저장 — reorderMyMenu 는 UPDATE 가 아니라 해당 사용자 행 전체 삭제 후 받은 순서대로 재삽입한다(결과적으로 MENU_SEQ 1,2,3… 재부여). 따라서 요청 본문은 항상 화면의 전체 목록이어야 하며, 일부만 보내면 빠진 항목이 즐겨찾기에서 사라진다. 프론트의 "편집 중 제거"는 이 성질을 의도적으로 이용한다.
    • INIT_YN 은 미사용 — 레거시 SidebarFavorite 의 "초기화면 지정" 북마크가 토글·저장하던 값이나, 레거시·V2 어디에도 읽는 코드가 없다. selectMyMenuList 가 NULL 을 'N' 으로 정규화해 내려보내고 reorderMyMenu 가 받은 값을 되쓸 뿐이다(그래서 편집을 거쳐도 기존 값은 보존된다). 랜딩 화면은 이 값이 아니라 순서로 정해진다.
    • MENU_EXPL 은 죽은 컬럼 — 등록 시 NULL 고정이며 읽는 코드가 없다(2026-08 운영 기준 전 행 NULL).

    4. 외부 연동 · 주의점¶

    Microsoft Graph 메일 연동¶

    아이디 찾기·비밀번호 초기화 메일은 VmsSendMicrosoftGraphMailService.sendMail이 발송한다(AdminService.java:220, :263).

    • 메일 본문은 Pebble 템플릿(mail/find-my-id, mail/find-my-password, mail/confirm-code)을 TemplateService.compile(...).render(...)로 렌더링.
    • Graph 인증정보(CLIENT_ID/TENANT_ID/CLIENT_SECRET/SCOPE)는 Oracle 프로시저 PKG_CM.SP_GET_AAD에서 동적 조회 → ClientSecretCredential로 GraphServiceClient 생성(VmsSendMicrosoftGraphMailService.java:70).
    • SDK는 Graph v6(Kiota): graphClient.users().byUserId(from).sendMail().post(...) 사용(VmsSendMicrosoftGraphMailService.java:267). 발송 후 PKG_CM_EMAIL.SP_SET_EMAIL로 발송 로그 적재.

    수신자 처리

    비밀번호 초기화는 사용자 등록 이메일(EMAIL)이 다중일 수 있어, 초기화 화면에서 받은 파라미터(userEmail)를 수신자로 사용한다(AdminService.java:254). 아이디 찾기 메일 실패는 스택트레이스만 출력하고 삼키지만(AdminService.java:222), 비밀번호 초기화 메일 실패는 예외를 던져 사용자에게 알린다(AdminService.java:266).

    비밀번호 정책¶

    • 인코딩은 BCryptPasswordEncoder(WebSecurityBeansConfiguration.java:199).
    • 변경 시 비밀번호 이력(TB_CMS_PWD_HISTORY)과 대조해 재사용을 막고(AdminService.java:184), 최소 사용기간 1일을 강제한다(isChangePasswordAfterOneDay, AdminService.java:770).
    • 로그인 5회 실패 시 잠금, 임시 비밀번호 발급 시 실패횟수 초기화(initPasswordFailCount).

    에러 로그 관리¶

    AdminService는 WriteErrorCodeService를 구현해 전역 예외를 처리한다.

    • getErrorValue(AdminService.java:659): AccessDeniedException/InsufficientAuthenticationException이면 MSG000041("권한이 없습니다.") 반환, 그 외에는 insertErrorLog로 TB_CMS_ERROR_LOG에 적재(@Transactional(REQUIRES_NEW), AdminService.java:752).
    • 적재 시 ERR_MSG 머리에 요청 요약을 덧붙인다(PR #97) — REQUEST:(메서드+URI+쿼리스트링) + PAYLOAD:(JSON 바디 pretty-print). 바디는 최우선순위 RequestResponseBodyCachingFilter 가 전 요청을 ContentCachingRequestWrapper 로 감싸 두어 예외 시점에도 판독 가능. 키 이름에 pwd/password/passwd/secret/token 이 들어간 값은 ***** 마스킹, multipart/binary 는 content-type·크기만, 텍스트 바디 4000자 캡. 요약 조립이 실패해도 빈 문자열 폴백 — 적재 자체는 막지 않는다. (이에 따라 VmsCommonService catch 의 별도 PARAMETERS 적재는 중복이라 제거됨.)
    • 에러 식별자는 X-Error-Code 헤더로 반환(getErrorHeader, AdminService.java:654). 호출 측은 GlobalHandlerExceptionResolver.
    • ERR_MSG 컬럼은 VARCHAR2→CLOB로 변경되어 4000바이트 절단 로직이 제거됨(AdminService.java:756 주석).

    참고: 관리자용 임의 SQL 실행 API(POST /api/runQueryCompiler)는 보안상 제거됐다(2026-07, 커밋 5256768).
