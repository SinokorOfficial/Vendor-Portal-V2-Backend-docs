    EIR (Electronic Interchange Receipt) 도메인 코드 워크스루¶

    상하이항(SIPG) ESB와 연동해 컨테이너 전자 교환증(EIR)을 발급/취소하고, 발급 결과(영수증번호 등)를 응답 로그 테이블에 적재하는 도메인이다. 외부 OAuth2 토큰은 Redis로 캐싱하며, 전송 본문은 MD5 Hash 또는 SHA-256 Signature로 무결성을 검증한다.

    1. 이 도메인이 하는 일¶

    • EIR 발급/취소: 포털에서 받은 컨테이너 항목들을 Oracle 프로시저로 JSON으로 변환해 SIPG ESB로 전송한다.
    • 토큰 관리: SIPG OAuth2 토큰을 회사코드(COMP_CD)별로 발급·검증·캐싱한다. Redis 기반(분산락 포함)이 현행이며, 구버전 ConcurrentHashMap 기반 서비스 메서드 EirService.getValidToken(:279)은 "사용 X" 주석의 비활성 잔재다 — 이를 노출하던 엔드포인트 GET /api/eir/getValidToken 은 2026-09-11 제거(PR #135).
    • 응답 로그 적재: SIPG 응답(영수증번호 receiptNo, 응답 메모)을 TB_EIR_RESPONSE_LOG에 INSERT하고, 누락 시 보정 조회로 채운다.
    • 회사 구분: SNKO(흥아라인)와 HALK(흥아) 두 회사코드에 대해 각기 다른 App-Id/Client-Id/시크릿을 사용한다 (EirService.java:150, EirService.java:156).

    구버전 vs 신버전

    과거엔 엔드포인트가 xxx / xxxNew 쌍으로 존재했으나, 구버전 엔드포인트(issueEir/cancelEir)와 getToken()/sendSIPG() 는 2026-08-21 삭제됐다(운영 로그상 죽은 API 확인 — 아래 5절 참고). 현재는 신버전(issueEirNew/cancelEirNew, getTokenNew/sendSIPGNew)만 존재하며, 이름의 New 접미는 이력상 유지된 것이다.

    구성 요소:

    레이어 클래스 / 파일 비고
    Controller EirController (controller/EirController.java:26) @RequestMapping("/api/eir"), ExtendBaseController 상속
    Service EirService (service/EirService.java:54) 외부 HTTP 호출·토큰·서명·로그 처리 전부 담당
    DAO EirDao (dao/EirDao.java:7) @VpRepository, 메서드는 insertEirLog 하나뿐
    Mapper Eir-mapper.xml (mapper/oracle/eir/Eir-mapper.xml:3) insertEirLog INSERT 1건

    DB 접근 경로

    EirDao/Eir-mapper.xml은 응답 로그 INSERT 1건만 담당한다. JSON 생성·영수증 로그·정보 조회 등 대부분의 DB 작업은 VmsCommonService.selectVmsCommonProcedure / saveVmsCommonProcedure를 통해 Oracle 패키지 PKG_EEIR의 프로시저(SP_RTNJASON, SP_SET_EIRLOG, SP_GET_EIR_INFO, SP_SET_EIR_INFO)를 호출하는 방식이다.

    2. 대표 유스케이스: EIR 발급 (POST /api/eir/issueEirNew)¶

    EirController.issueEirNew (controller/EirController.java:62)는 컨테이너 항목 리스트를 받아 항목별로 다음을 수행한다.

    sequenceDiagram
    participant FE as Frontend
    participant C as EirController
    participant S as EirService
    participant R as Redis
    participant V as VmsCommonService (PKG_EEIR)
    participant SIPG as SIPG ESB (gdtspace)

    FE->>C: POST /issueEirNew (List<DMap>)
    C->>S: getValidTokenNew(compCd)
    S->>R: token:{compCd} 조회 + 유효성 검사
    alt 캐시 만료/없음
        S->>R: setIfAbsent(lock) 분산락 획득
        S->>SIPG: getTokenNew() OAuth2 토큰 발급
        S->>R: token 저장 (만료 30초 전)
    end
    R-->>S: validToken
    loop 항목별
        C->>S: setJson(userId, item)
        S->>V: SP_RTNJASON (JSON 생성)
        V-->>S: JSON(outRefNo 포함) 또는 [ERROR]
        C->>S: sendSIPGNew(token, compCd, ... opStatus="0", json)
        S->>SIPG: POST EIR3.0~B01~200001 (X-Signature=SHA256)
        SIPG-->>S: {status, data.receiptNo, ...}
        S->>S: insertEirLog → TB_EIR_RESPONSE_LOG
        C->>S: setEirResponse(userId, sendResult)
        S->>V: SP_SET_EIRLOG (영수증 로그 갱신)
        C->>S: updateEirInfo (receiptNo 누락분 보정)
    end
    C-->>FE: ResponseVo { RESULT: [...] }

    단계 요약 (controller/EirController.java:53~147):

    1. 토큰 발급 — getValidTokenNew(compCd)로 Redis 캐시 토큰 확보 (service/EirService.java:298).
    2. JSON 생성 — setJson이 PKG_EEIR.SP_RTNJASON 프로시저로 전송 JSON을 만든다. 결과가 [ERROR]로 시작하면 즉시 에러 응답 반환 (controller/EirController.java:93).
    3. EIR 전송 — sendSIPGNew(token, compCd, userId, bkNo, cntrNo, imex, eirNo, opStatus, jsonResult). opStatus는 발급="0", 취소="2" (controller/EirController.java:122 / :211). ★userId 는 세션 권위다(getSession().getUserId(), PR #135) — 종전엔 요청 본문의 USER_ID 를 그대로 썼다.
    4. 응답 로그 갱신 — setEirResponse가 PKG_EEIR.SP_SET_EIRLOG를 호출 (service/EirService.java:795).
    5. 영수증 보정 — updateEirInfo가 receiptNo 누락분을 조회 API로 채운다 (service/EirService.java:1000).

    발급/취소 차이

    cancelEirNew(controller/EirController.java:149)는 issueEirNew와 거의 동일하나 sendSIPGNew의 opStatus를 "2"로 보내고, updateEirInfo 보정 단계가 없다.

    3. 토큰 관리 흐름 (Redis)¶

    getValidTokenNew (service/EirService.java:298)의 동작:

    • 키: token:{compCd}, 만료 token_exp:{compCd}, 분산락 lock:token:{compCd}.
    • 1차로 캐시 토큰을 checkTokenValidate(SIPG OAuth2~S01~100001 호출, service/EirService.java:455)로 검증하고 만료시각 이전이면 그대로 반환.
    • 만료 시 setIfAbsent(lockKey, "1", 10s)로 분산락을 잡고 신규 발급(getTokenNew, service/EirService.java:136). 만료 30초 전 시각으로 캐시 (service/EirService.java:342).
    • 락 획득 실패 시 150ms 간격 최대 20회 폴링, 끝내 실패하면 RuntimeException("[Redis] EIR Token acquisition timeout") (service/EirService.java:370).

    캐시 조회 엔드포인트 GET /api/eir/getCachedToken은 getRedisToken(service/EirService.java:431)으로 token:* 키를 스캔해 반환한다. 토큰은 admin 포함 모든 사용자에게 앞 10자만 노출한다 (service/EirService.java:416).

    4. 핵심 엔드포인트¶

    메서드 경로 설명
    GET /api/eir/getCachedToken Redis 캐시 토큰 목록 조회(getRedisToken). 토큰은 앞 10자만 노출 (:40). EirResponseLog.fnSearchToken 이 사용
    POST /api/eir/issueEirNew EIR 발급 (Redis 토큰 + sendSIPGNew, opStatus "0")
    POST /api/eir/cancelEirNew EIR 취소 (opStatus "2")
    POST /api/eir/getEirInfo SIPG 조회 API로 EIR 정보(영수증번호 등) 조회(getEirInfo4Web) (:237). EirResponseLog.fnSearchSIPG 가 사용

    ~~GET /api/eir/getValidToken~~ 은 2026-09-11 제거(PR #135) — 호출부 0건이었고 SIPG 토큰을 그대로 반환하는 표면이었다. 5개 엔드포인트 전부 세션 인증 필요(permit-all 해제, 같은 PR).

    인용 라인은 모두 src/main/java/com/sinokor/vp/eir/controller/EirController.java 기준.

    5. 외부 연동 · 주의점¶

    외부 엔드포인트 (버전별 상이) — 구버전 컬럼은 2026-08-21 정리로 코드에서 삭제된 경로의 이력 참고용.

    용도 구버전 (getToken/sendSIPG, 삭제됨) 신버전 (getTokenNew/sendSIPGNew)
    Base URL https://SIPG-ESB-HOST.cn/ParaEsb/... https://ESB-HOST/api/
    인증 헤더 Token: {token} (:613) Authorization: Bearer {token} (:668)
    무결성 Md5Code = MD5(body) (:601,:618) X-Signature = SHA-256(Body=+Base64(body)+&+SALT) (:670)
    서비스 코드 serviceName: S0010006A (:617) EIR3.0~B01~200001 (:653)

    라인은 service/EirService.java 기준. 토큰 발급 신버전은 OAuth2~S01~100000(:143), 검증은 OAuth2~S01~100001(:459), 정보 조회는 EIR3.0~B01~500002(:872).

    서명 / 회사별 SALT — generateSignature (service/EirService.java:555): SNKO=hF1SO3kE, HALK=oECaa00P. 본문 공백 제거 후 Base64 → Body={base64}&{SALT} → SHA-256 → Base64.

    시크릿 외부화

    Client-Secret / Password는 @Value로 application.yaml(gitignore)에서 주입한다. 키: eir.snko.client-secret, eir.snko.password, eir.halk.client-secret, eir.halk.password (service/EirService.java:67~74, 템플릿 application.yaml.example:237~243). 하드코딩/커밋 금지.

    구버전 코드의 평문 시크릿 — 해소 완료

    ~~구버전 경로의 평문 자격증명~~ → 2026-08-21 정리 완료: 구형 엔드포인트 3종(/api/eir/issueEir·/api/eir/cancelEir·/api/partner/getToken)과 EirService.getToken()/sendSIPG(), PartnerService 의 주석 처리된 구 getToken 블록을 삭제해 평문 자격증명(authStr/username/password)이 소스에서 소멸했다(운영 API 로그 실측: /api/partner/getToken(EIR001) 마지막 호출 2025-12-30 — 죽은 API 확인 후 제거). 잔여: ~~①/api/eir/** permit-all 제거~~ → 2026-09-11 완료(PR #135, Infra #17 종결) ②~~(선택) SIPG 크리덴셜 로테이션~~ → 종결·실행 불가(상대 창구 없음, Infra #25) ③generateSignature 의 SALT 2종은 신버전도 사용하므로 존치(별건).

    기타 주의점

    • SIPG 통신 자체가 실패(연결 불가·타임아웃 — httpClient.execute 의 IOException)하면 4개 호출 지점(getTokenNew·checkTokenValidate·sendSIPGNew·getEirInfoFromSIPG) 모두 ExternalServiceException 으로 래핑돼 502 + MSG000430("SIPG 서버 오류로 통신할 수 없습니다…")으로 응답한다(PR #109, 2026-08-27 — 레거시 동일 반영). 범용 500 이 아니라서 사용자가 포털 장애로 오인하지 않으며, 5xx 유지라 경보 대상은 그대로다. 그 외 예외는 기존 500(단, 토큰 발급 실패는 아래 불릿처럼 502).

    • ESB 가 응답은 했는데 본문이 비었거나 JSON 이 아닐 때(PR #115·#116, 2026-09 — 레거시 동일 반영)의 처리는 지점별로 다르다. ① getTokenNew — 파싱 불가/access_token 부재/expires_in 누락·비숫자 전부 실패 확정: 상태코드·본문 앞부분(describeBadResponse, 200자 캡)을 담은 ExternalServiceException(502+MSG000430). 종전엔 빈 DMap 반환 → 호출부 Long.parseLong(null.toString()) NPE 로 ESB 의 실패 사유가 유실됐다. ② checkTokenValidate — "false" 강등으로 호출부(getValidTokenNew)의 토큰 재발급 경로로 흘린다(예외를 올리면 그 복구 경로 도달 자체가 막힌다). ③ getEirInfoFromSIPG — 흡수(로그만): 발급 후처리(RECEIPTNO 보충)라 예외를 올리면 이미 성공한 발급이 화면에 실패로 보인다(운영 실제 발생 사례). RESULT 미적재 시 호출부가 건너뛰므로 기존 400 분기와 동작 동일. sendSIPGNew 의 응답 파싱은 기존 catch 가 이미 흡수하므로 변경 없음.

    • sendSIPGNew는 SIPG가 응답한 경우(200+receiptNo / 200+빈 receiptNo / 4xx 오류응답)를 전부 insertEirLog로 응답 로그에 남기고, 응답 자체가 없는 예외에서만 adminService.insertErrorLog(... "04" ...)를 쓴다 (service/EirService.java:733, :742, :766, :780).

    • setEirResponse의 빈 커서 분기는 에러가 아니다 — SP_SET_EIRLOG가 SIPG 실패 응답(RESPONSEMEMO 있고 RESPONSEFIELD 없음)에서 eEir_send_log 행을 지우고 커서를 열지 않은 채 return 하는 설계된 경로다. 실패 내용은 sendSIPGNew가 이미 응답 로그에 남겼으므로 여기서는 로그 없이 빈 결과를 그대로 반환한다 (service/EirService.java:828).
    • updateEirInfo(service/EirService.java:1000)는 발급 직후에만 조회 가능하다는 SIPG 제약 때문에 추가된 보정 로직이다(주석 service/EirService.java:867).
    • 응답 로그 INSERT는 TB_EIR_RESPONSE_LOG, API_KEY 컬럼에는 [V2] 마커 + 토큰 앞 10자가 들어간다(레거시 발급분과 구분용 — 과거 PID 조합은 주석 처리) (service/EirService.java:100, mapper/oracle/eir/Eir-mapper.xml:7).
