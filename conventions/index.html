    코드 컨벤션¶

    VP 백엔드는 타입 DTO/JPA 대신 동적 맵(DMap)을 데이터 캐리어로 쓰고, 응답은 ResponseVo로 일관되게 감싸며, 영속성은 MyBatis XML 매퍼 + @VpRepository 마커 인터페이스로 처리한다. 이 문서는 그 핵심 규약을 실제 소스 기준으로 정리한다.

    레이어 구조¶

    @RestController → @Service → DAO(@VpRepository) → MyBatis XML 매퍼로 흐른다.

    flowchart LR
    C["@RestController<br/>요청 파싱 · ResponseVo 빌드"] --> S["@Service<br/>비즈니스 로직 · @Transactional"]
    S --> D["@VpRepository DAO<br/>(메서드 시그니처만)"]
    D --> X["*-mapper.xml<br/>(oracle SQL)"]
    레이어 마커/패턴 책임
    controller @RestController + @RequestMapping @RequestBody DMap 파싱, ResponseVo.of(...).build() 반환
    service @Service + @Transactional DMap 조작, 트랜잭션 경계, 검증
    dao @VpRepository MyBatis 매퍼 인터페이스(구현 없음)

    활성/메시지

    컨트롤러는 ExtendBaseController, 서비스는 ExtendBaseService를 상속해 getUserId(), getMessage(...), errorMessage(...) 등 공통 기능을 쓴다. (mdm/code/controller/MdmPortMgtController.java:21, mdm/code/service/MdmPortMgtService.java:18)

    DMap — 데이터 캐리어¶

    DMap은 HashMap<String, Object>를 상속한 타입 게터 컨테이너다 (core/vo/DMap.java:14). 조회/저장 전 구간에서 이걸 쓰며, DTO를 만들지 않는다.

    타입 게터 (null/빈값 안전)¶

    게터는 값이 없거나 변환 실패 시 예외 대신 기본값을 돌려준다.

    게터 반환/기본값 근거
    getString(key) String, 없으면 "" core/vo/DMap.java:18
    getInt(key) / getLong(key) / getDouble(key) 숫자, 없거나 빈문자면 0 core/vo/DMap.java:34,40,46
    getBigDecimal(key) BigDecimal, 기본 new BigDecimal(0) core/vo/DMap.java:52
    getLocalDateTime(key) / getLocalDate(key) Timestamp/LocalDateTime/String 자동 변환, 없으면 null core/vo/DMap.java:64,82
    getTimestamp(key) Timestamp, 없으면 null core/vo/DMap.java:58
    getStringList(key) List<String>, 없으면 빈 리스트 core/vo/DMap.java:28
    getMap(key) 중첩 맵을 DMap으로 복사, 없으면 null core/vo/DMap.java:114
    getMapList(key) List<DMap>, 없으면 빈 리스트 core/vo/DMap.java:123
    getMultipartFile(key) / getMultipartFiles(key) 업로드 파일 core/vo/DMap.java:102,108

    숫자 게터는 String 파싱

    getInt 등은 내부적으로 Integer.parseInt(value.toString())를 호출한다 (core/vo/DMap.java:36). 숫자가 아닌 문자열이 들어오면 NumberFormatException이 난다. 빈문자열("")과 null만 0으로 처리된다.

    생성 — 정적 팩토리 / 빌더¶

    단건은 asMap, 누적 변형은 initBuild()(MapBuilder)를 쓴다.

    // 정적 팩토리 (core/vo/DMap.java:144)
DMap one = DMap.asMap("PORT_CD", "PUS");

// 빌더 — put/remove/replace 후 build() (core/vo/DMap.java:182, 196~217)
DMap built = param.initBuild()
                  .putBuilder("USER_ID", userId)
                  .removeBuilder("TEMP")
                  .build();

    Note

    MapBuilder의 메서드명은 putBuilder / putAllBuilder / removeBuilder / replaceBuilder이며, initBuild()는 원본을 복사한 새 맵으로 시작한다(원본 불변). 단순 사용은 그냥 put / getMap / getMapList로 충분하다.

    ResponseVo — 응답 포맷¶

    모든 컨트롤러 응답은 ResponseVo<T>로 감싼다 (core/vo/ResponseVo.java:8). JSON 직렬화 형태:

    { "code": "200", "message": null, "data": { }, "traceId": "..." }
    • code 미지정 시 기본 "200" (core/vo/ResponseVo.java:21).
    • traceId는 Trace.getId()로 자동 주입 — 직접 넣지 않는다 (core/vo/ResponseVo.java:22).
    • 빌더는 정적 팩토리 of(data) / of()(데이터 없는 Void)로 시작한다 (core/vo/ResponseVo.java:25,29).
    // 데이터 응답 (mdm/code/controller/MdmPortMgtController.java:28)
return ResponseVo.of(resultMap).build();

// 데이터 없는 응답 (같은 파일 :37)
return ResponseVo.of().build();

// 메시지/코드 지정
return ResponseVo.of(data).message("저장되었습니다").code("200").build();

    오류 응답은 ResponseErrorVo.exception(ex) 빌더로 만든다. 기본 code는 "500", type은 예외 클래스 단순명이 자동 세팅된다 (core/vo/ResponseErrorVo.java:11,46).

    @VpRepository — DAO 마커¶

    @VpRepository는 MyBatis 매퍼 인터페이스를 표시하는 타입 어노테이션이다 (config/annotation/VpRepository.java:8). MyBatis 표준 @Mapper를 쓰지 않는다.

    스캔은 @MapperScan(basePackages = "com.sinokor.vp", annotationClass = VpRepository.class)로 한 곳에서 일괄 등록한다 (config/database/VpDataBaseConfiguration.java:30).

    // admin/dao/AdminDao.java:10
@VpRepository
public interface AdminDao {
    DMap selectUser(@Param("USER_ID") String USER_ID, @Param("CORP_CD") String CORP_CD);
    List<DMap> selectRoleId(@Param("USER_ID") String USER_ID, @Param("CORP_CD") String CORP_CD);
    void updateUser(DMap user);
}

    규약:

    • 인터페이스만 두고 구현은 동명 매퍼 XML이 담당한다.
    • 메서드명 = 매퍼 XML의 쿼리 id.
    • 반환은 DMap / List<DMap> / 원시 타입(int, String).
    • 파라미터가 여러 개면 각각 @Param("KEY")로 매핑 키를 명시하고, DMap 하나면 그대로 넘긴다.

    MyBatis 매퍼 XML¶

    위치는 src/main/resources/mapper/oracle/<module>/<Name>-mapper.xml이다. 어노테이션 SQL은 쓰지 않는다.

    • namespace는 대응 DAO의 FQCN (mapper/oracle/mdm/code/MdmPortMgt-mapper.xml:3).
    • 첫 줄 주석 /* module.dao.ClassName.methodName */로 로그에서 쿼리를 추적한다 (같은 파일 :6).
    • resultType="dmap" / parameterType="dmap" — dmap은 mybatis-config.xml의 typeAlias (mapper/mybatis-config.xml:10).
    • 파라미터 바인딩은 #{KEY} (DMap 키 또는 @Param 이름).
    <!-- mapper/oracle/mdm/code/MdmPortMgt-mapper.xml:5 -->
<select id="select" parameterType="dmap" resultType="dmap">
    /* mdm.code.dao.MdmPortMgtDao.select */
    SELECT PORT_CD, PORT_NM
      FROM TB_MDM_PORT
     WHERE 1 = 1
    <if test=' PORT_CD != null and PORT_CD != "" '>
        AND PORT_CD LIKE CONCAT( #{PORT_CD}, '%' )
    </if>
    ORDER BY PORT_CD
</select>

    분기는 <if> 또는 <choose>/<when>/<otherwise>로 작성한다:

    <!-- mapper/oracle/admin/Admin-mapper.xml:80 -->
<choose>
    <when test="CORP_CD != null and CORP_CD != ''">
        AND A1.CORP_CD = #{CORP_CD}
    </when>
    <otherwise>
        AND A1.MAIN_YN = 'Y'
    </otherwise>
</choose>

    페이징 (PageHelper)¶

    목록 페이징은 서비스에서 PageHelper.startPage(currPage, perPage)를 호출한 직후의 DAO 조회에 적용된다. 반환은 Page<DMap>이며 getPages() / getTotal()로 페이지·전체 건수를 얻는다.

    // cms/popup/service/CmsCommonPopupService.java:37
PageHelper.startPage(currPage, perPage);
Page<DMap> list = commonPopupDao.selectCommon(searchMap);
retMap.put("PAGE_LENGTH", list.getPages());
retMap.put("PAGE_TOTAL", list.getTotal());

    PageHelper 설정 유지

    application.yaml의 pageSizeZero: true(PageHelper 1.4.x 동작 복원)는 삭제 금지다. 또한 Oracle 페이징이 누출하는 합성 컬럼 PAGEHELPER_ROW_ID는 PageHelperRowIdStripInterceptor가 제거한다 (config/database/VpDataBaseConfiguration.java:84).

    컨트롤러 / 서비스 작성 패턴¶

    전형적인 CRUD 한 묶음. 컨트롤러는 얇게(파싱·조립), 서비스가 트랜잭션과 분기를 가진다.

    // controller (mdm/code/controller/MdmPortMgtController.java:33)
@PostMapping("/save")
public ResponseVo<Void> save(@RequestBody DMap param) {
    param.put("USER_ID", getUserId());
    mdmPortMgtService.save(param);
    return ResponseVo.of().build();
}

    // service (mdm/code/service/MdmPortMgtService.java:34)
@Transactional
public void save(DMap param) {
    String userId = param.getString("USER_ID");
    for (DMap map : param.getMapList("PORT_GRID")) {   // 그리드 행 단위
        map.put("USER_ID", userId);
        switch (map.getString("BATCH_FLAG")) {          // 행별 I/U/D 분기
            case INSERT -> { validPort(map); mdmPortMgtDao.insert(map); }
            case UPDATE -> mdmPortMgtDao.update(map);
            case DELETE -> mdmPortMgtDao.delete(map);
        }
    }
}

    규약 포인트:

    • 그리드(목록) 저장은 행별 BATCH_FLAG(INSERT/UPDATE/DELETE)를 보고 분기한다 (MdmPortMgtService.java:34~55, 상수는 core/code/BatchFlag의 static import).
    • 검증 실패는 errorMessage("MSG코드", 인자).build()를 throw — 메시지 코드는 다국어 테이블에서 해석된다 (MdmPortMgtService.java:26 validPort).
    • 응답 맵의 키(PORT_GRID 등)는 프런트 dataset과 합의된 이름을 쓴다.

    타입 컨벤션: DTO/JPA 지양¶

    • 모든 조회/저장은 DMap으로 한다. 타입 변환 계층(DTO ↔ Entity)을 두지 않는다 — 동적 필드, 반복문 내 필드 추가, 레거시 호환을 위해서다.
    • 예외는 보안 도메인뿐: LoginUser(Spring Security User 상속), GuestAuthentication(UsernamePasswordAuthenticationToken 상속)처럼 프레임워크가 타입을 요구하는 곳만 클래스를 둔다.
    • JPA 리포지토리/엔티티 매핑은 도입하지 않는다.

    bin/ 편집 금지¶

    bin/은 로컬 IDE(Eclipse) 빌드 미러로 .gitignore 대상이다. 편집 금지 — 항상 src/main/...을 고치고, 산출물은 ./gradlew bootJar(build/libs/vp-backend.jar)만 인정한다.

    Note

    build/ 아래 mapper/oracle/... 파일도 빌드 복사본이다. 매퍼 수정은 반드시 src/main/resources/mapper/oracle/... 원본에서 한다.
